# 系统启动方法与路径速查

> 万州区生态环境局智能 AI 大数据驾驶舱
> 涵盖两种启动场景：**开发/源码态** 与 **生产态（方案B）**

---

## 一、系统组成（先理解再启动）

| 组件 | 进程 | 端口 | 说明 |
| --- | --- | --- | --- |
| 前端 | 开发态 Vite / 生产态 Nginx | 5173(开发) / 80(生产) | React 单页应用 |
| 后端 | Node `index.js` | 7170 | Express，数据存 SQLite（`server\data\jsc.db`） |
| MQTT Broker | 外部（如 EMQX） | 8083(WS) | 浏览器**直连**收传感器数据 |
| ZLMediaKit | 外部（Docker） | 按配置 | 视频流转发，浏览器**直连**播放 |

> 前端与后端是系统本体；MQTT、ZLM、云MAS短信、高德地图为外部依赖，按需对接。
> **启动顺序**：后端 → 前端。外部依赖（ZLM/MQTT）可先可后，影响对应功能可用性。

## 二、开发 / 源码态启动（本机调试、演示）

源码目录：`E:\CC work\CC jsc`

### 方式 A：一键脚本（推荐）

```powershell
cd "E:\CC work\CC jsc"
.\start.ps1
```

`start.ps1` 会：检查并尝试启动 ZLMediaKit 容器 → 新窗口启后端(7170) → 新窗口启前端(5173 dev)。
两个 PowerShell 窗口保持打开即运行中，关闭即停止。

访问：`http://localhost:5173`（或 `http://<本机IP>:5173`）

### 方式 B：手动分步（排错时用）

```powershell
# 终端1 — 后端
cd "E:\CC work\CC jsc\server"
npm start
# 首次启动控制台会打印默认管理员账号：admin / admin123（首登强制改密）

# 终端2 — 前端
cd "E:\CC work\CC jsc"
pnpm dev --host
```

开发态前端走 Vite dev server，`/api` 由 `vite.config.ts` 的 proxy 自动转发到 `localhost:7170`，无需 Nginx。
浏览器打开后会先进**登录页**，用账号密码登录（不再需要 API Key）。

## 三、生产态启动（方案B，服务器 C:\jsc）

生产部署后，**后端是常驻 Windows 服务、Nginx 托管前端**，不需要每次手动开窗口。

### 正常运行态：开机即自启

- 后端服务 `JscBackend`（NSSM）：`SERVICE_AUTO_START`，开机自动起、崩溃自动重启。
- Nginx：建议也注册为服务/随机启动（见下）。

服务器开机后系统即自动可用，访问 `http://<服务器IP>/`。

### 手动启动 / 重启（运维时）

```powershell
# —— 后端 ——（NSSM）
C:\jsc\tools\nssm.exe start    JscBackend
C:\jsc\tools\nssm.exe restart  JscBackend      # 更新后端代码后用
C:\jsc\tools\nssm.exe stop     JscBackend
C:\jsc\tools\nssm.exe status   JscBackend

# —— Nginx ——
cd C:\jsc\nginx
.\nginx.exe              # 启动
.\nginx.exe -s reload    # 重载配置（改了 jsc.conf 后）
.\nginx.exe -s stop      # 停止
.\nginx.exe -t           # 测试配置语法
```

### 发布新前端版本

```powershell
cd C:\jsc
.\deploy\deploy.ps1            # 构建 + 发布 dist + reload nginx
.\deploy\deploy.ps1 -Rollback  # 回滚到上一版
```

### 让 Nginx 开机自启（可选，二选一）

```powershell
# 用 NSSM 也把 nginx 注册成服务
C:\jsc\tools\nssm.exe install JscNginx C:\jsc\nginx\nginx.exe
C:\jsc\tools\nssm.exe set     JscNginx AppDirectory C:\jsc\nginx
C:\jsc\tools\nssm.exe set     JscNginx Start SERVICE_AUTO_START
C:\jsc\tools\nssm.exe start   JscNginx
```

## 五、启动后验证

```powershell
# 后端健康（直连）
Invoke-RestMethod -Uri "http://localhost:7170/api/health"
Invoke-RestMethod -Uri "http://localhost:7170/api/health/files"

# 生产态经 Nginx 走一遍
Invoke-RestMethod -Uri "http://localhost/api/health"
```

返回 `status: ok` 且各项条数正常即启动成功（`health/files` 各项现以 `db:true; count:N` 形式返回库内条数）。
浏览器打开首页后会进**登录页**，用账号密码登录。

### 登录账号

首次启动后端时控制台会打印**默认管理员**：

```
用户名: admin
密码:   admin123   （首次登录强制改密）
```

登录后进管理后台「用户管理」可新建值守员/访客账号、分配角色、重置密码。
忘记管理员密码的应急方式：停后端 → 用 SQLite 工具打开 `server\data\jsc.db` 删除 users 表中该行 → 重启后端会重新种 `admin/admin123`。

## 六、常见启动问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 前端报"无法连接后端服务" | 后端没起 / 7170 不通。开发态查终端1，生产态 `nssm status JscBackend` 看是否 RUNNING |
| 登录后操作提示"权限不足" | 当前账号角色不够（访客只读、值守不能改配置）。用管理员账号或在「用户管理」提升角色 |
| 提示"未登录或会话已过期" | 重新登录即可；会话默认 7 天有效 |
| 地图加载不出 | 需互联网访问高德；或 `.env` 的 Key 失效。改 Key 后**生产态需重新 `deploy.ps1` 构建** |
| 视频流打不开 | ZLMediaKit 未启动或地址变更，到管理后台「视频流管理」核对 |
| MQTT 一直未连接 | broker 地址/8083 端口不通，管理后台「MQTT 配置」核对 |
| 短信回调 403 | 平台出口 IP 不在 `jsc.conf` 白名单，更新 `geo $sms_callback_allowed` 后 reload |
| `pnpm install` 报 git 拉取失败 | 未装 Git；本系统部分依赖从 GitHub 拉取，必须装 Git |
