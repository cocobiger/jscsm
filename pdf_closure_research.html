智治推送第③环「PDF 结案存档」技术选型调研

目标：事件推送城运中心 → 处置回执闭环后，按甲方模板生成结案 PDF 并存档　|　调研日期：2026-07-12

一句话结论

GitHub 上最成熟的套路是「模板与代码分离 + 数据注入」：把甲方版式做成一份可编辑模板（HTML 或 JSON Schema），运行时把结案数据填进去再渲染成 PDF。结合本项目现状（Node 后端 + 服务器已装 Playwright/Chromium、且 P0–P2 已把"非技术人员可配置"作为主线），最稳的落地路径是：

  • MVP（推荐先做）：HTML + Handlebars 套版模板，用 Playwright page.pdf() 打印。复用现有 Chromium，1:1 还原甲方红头/印章/表格最忠实，零新增重依赖。
  • 增强（甲方自服务）：内嵌 pdfme 可视化设计器，让不懂技术的人拖拽摆字段、存为 JSON 模板，Node 端 @pdfme/generator 直出 PDF（无需浏览器）。

二、关键发现（直接决定怎么设计）

① 模板必须独立于代码。 所有成熟仓库都把"模板"作为可编辑资源（HTML 字符串 / JSON Schema / Word），运行时注入数据。→ 本案应新增一张「结案报告模板」表存 DB，在智能推送管理页里可编辑 + 实时预览，与现有 platforms.body_template 思路一脉相承。
② 非技术自服务靠"可视化设计器"。 pdfme 的 Designer 是 Google Slides 式拖拽，甲方人员可直接摆字段、红头标题、印章图片，存为 JSON。这最契合 P0–P2 的"让不懂技术的人简单操作"主线。
③ 1:1 还原靠"HTML 复刻"。 甲方给的是扫描件 / Word 红头公文时，最忠实还原的方式是实施同学用 HTML/CSS 1:1 复刻，再 Playwright 打印成 PDF（矢量、文字可选、支持页眉页脚页码、水印印章）。GitHub 上此类仓库最多、模式最成熟。
④ 中文是头号坑（必须前置处理）。 无头 Chromium 在 Linux 服务器缺 CJK 字体 → 方块/空白。通用解法：apt install fonts-noto-cjk（或 wqy）；CSS 显式 font-family；必要时 @font-face base64 内联（its-abdullah 仓库即此法）。第一步务必确认服务器 fc-list :lang=zh 有输出。
⑤ 本项目已具备 Playwright + Chromium。 DJI 桥接已在用 Playwright。PDF 打印只需 chromium.launch({headless:true}) + page.pdf()，无需 Xvfb（打印不依赖显示），零新增重依赖。
⑥ 性能与并发。 打印是秒级、吃内存。结案报告属低频触发（闭环时生成），非高并发，单实例足够；可加简单队列/限流以防批量结案。

三、推荐架构

结案触发
(status→closed / 手动结案) → 数据聚合
history+events+平台+处置人/结果/证据图 → 模板渲染
HTML/Handlebars 或 pdfme JSON → PDF 存档
/data/reports/{id}.pdf → 管理页"导出结案报告"下载

模板层

新增表 smart_push_report_templates(id, name, engine, content, created_at)。管理页提供两种编辑模式：

  • 模式 A「HTML 套版」（默认，给开发/实施）：CodeMirror 编辑 HTML+Handlebars，右侧实时预览。最保真。
  • 模式 B「可视化设计」（给甲方/非技术）：内嵌 pdfme Designer，拖拽生成 JSON Schema，存回 content。

数据层

closureReportData(historyId) 组装变量：事件类型/时间/经纬度/推送平台/预案、处置结论 disposal_result、处置人 disposal_operator、结案时间 closed_at、关联预警/证据图（经 iot-image 代理）。

渲染层

  • engine=html → Playwright page.setContent(compiledHtml) → page.pdf({format:'A4', printBackground:true, headerTemplate, footerTemplate(页码), margin})
  • engine=pdfme → @pdfme/generator 的 generate({template, inputs})（Node 直出，无浏览器）

存档层

PDF 写 /opt/jsc/backend/data/reports/{historyId}.pdf；history 表加 report_path / report_generated_at；管理页加"导出结案报告"按钮；（可选）把 PDF 回传城运中心，闭环第③环。

四、两种模板模式怎么选

场景选哪个理由
甲方给电子/扫描公文样本，追求 1:1 还原HTML 套版（Playwright）像素级复刻红头/印章/表格，矢量文字可选
甲方想自己改版式、无开发资源pdfme 可视化设计拖拽即所得，JSON 存库，Node 直出
MVP 快速见效先做 HTML 套版复用现有 Chromium，落地最快、最保真；pdfme 作增强

五、建议实施路线

0
服务器就绪验证：fc-list :lang=zh 查 CJK 字体；确认 Playwright Chromium 可用；缺字体则 apt install fonts-noto-cjk 并 fc-cache -fv。
1
POC 验证：写一份样例"结案报告"HTML 模板 + 一个 Node 渲染脚本（Playwright），产出 1 份样例 PDF 交甲方确认版式。
2
数据聚合：实现 closureReportData(historyId)，把 history/events/平台/处置信息/证据图组装为变量。
3
模板表 + 管理页编辑器（先 HTML 模式）：建表、列表/编辑/预览。
4
渲染服务 + 存档 + 下载：结案自动生成、写盘、history 记录路径、前端导出按钮。
5
增强：pdfme 可视化设计器；自动触发；PDF 回传城运中心（闭环第③环）。

六、风险 & 前置

  • 必做 CJK 字体：服务器不装中文字体，PDF 必成方块。
  • 低风险 Chromium 路径/权限：DJI 桥接已在用，基本无虞。
  • 注意 复杂表格/跨页：HTML 用 @media print、break-inside:avoid 防止分页截断。
  • 注意 印章/红头：以图片 schema 或 CSS 绝对定位叠加实现。
