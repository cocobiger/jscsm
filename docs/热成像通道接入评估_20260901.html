1. 样本对比（DJI_20260827191659_0004，黄昏）

V 通道（可见光）— 含细微远烟带
T 通道（热成像）— 烟信号被云覆盖，看不出

该样本拍摄时间 19:16 黄昏，云层丰富，地表热源主要是城市建筑/工业。远景烟柱热信号弱于周边建筑/工业，被平滑淹没。

2. M30T T 通道特性

特性说明对秸秆烟检测的影响
分辨率640×512（V 是 1920×1080）劣势 远景小目标信息少
测温范围-20°C ~ 150°C（高增益）/ 0~500°C（低增益）中性 烟柱温度 30~80°C 在量程内
夜视能力无补光依赖热辐射，夜间强优势 夜间烟雾/火光高对比
白天场景建筑/裸地/水面温差大，干扰多劣势 黄昏/白天远烟淹没
云层穿透云本身冷（紫色），覆盖下方热源劣势 本场景多云，烟信号被遮挡
大烟检测火点温度 >500°C，与背景温差 200°C+优势 夜间大火/明火显著

3. 场景适配分析

场景V 通道T 通道推荐策略
白天 1km+ 远烟（主流场景）主检测信号弱仅 V
白天近距离大烟（<500m）主检测辅助V + T 互补
夜间大烟（无云遮挡）主检测（V 增益低）主检测T 主 + V 辅
夜间明火/大烟（>500°C）火光可见热斑显著T 强信号
黄昏/多云云烟混淆云遮挡两通道都弱

4. 当前数据现状

  • DJI 双光照片：5 对（DJI_20260826/27），存于 /video/shujuji/xunlian/evidence/media/
  • V 通道样本：黄昏云层丰富，远景细微烟带（与 v5 真实场景一致）
  • T 通道样本：冷天空 + 城市热斑，看不出明显烟信号
  • 司空2 已配 webhook FILE_UPLOAD，可自动同步双光照片到 MinIO

5. 接入路径设计（如需启用）

  1. 数据流：M30T 双光 → 司空2 (OSD/拍照) → MinIO (tenantResource/special/.../dock_media/) → 我方 MinIO 同步 (infra/vlm/media_sync_v5.py)
  2. 推理流：双通道分别 ONNX 推理 → V 通道高分告警 + T 通道热斑辅助验证
  3. 模型需求：T 通道专用 YOLO/UNet，需 200+ 张热成像烟样本微调（当前 0 张）
  4. 存储开销：每张双光 ~3MB（V 1.7M + T 1.3M），5 对约 15MB
  5. 开发成本：T 通道模型采集 + 标注 ~3~5 天，T 推理适配 ~1 天

6. 结论

当前阶段：不接入 T 通道主检测，仅作 V 通道告警的"夜间/明火"二次验证信号。

理由：
  1. v5 主流场景（白天 1km+ 远烟）T 通道信号弱于 V 通道，接入 ROI 低
  2. T 通道训练样本 = 0，需先积累 200+ 张夜间大烟/明火热成像样本
  3. 双通道分别建模 + 同步推理会增加 straw-engine 1.5~2 倍 GPU 算力开销（当前 3090 已被占 4.9G，剩 19.7G 可用但紧张）
  4. v5 训练样本治理（P3-2a/2b）优先级更高，先解决主通道数据再考虑副通道
触发条件（任一满足即启动接入）：
  1. 夜间大烟/明火告警样本积累 ≥50 张真实 + ≥200 张合成
  2. v5 v6 主通道 mAP50 达到 ≥0.6 后投入 T 通道增量训练
  3. 客户要求 24h 全场景（含夜间明火）覆盖
