3. 判断依据链（为什么说是"映射被改"而不是"机器重装丢数据"）

观察推论
:81 从"外网 200"变成完全未开放 jsc 的公网 HTTP 映射已被删除或改指
:22333 从 SSH-2.0-OpenSSH 变成 TLS CN=DaQiServer 该映射被重新指向了另一台机器（不是 8.12 上"换了服务"那么简单）
:9501/9533 仍映射到我方 DESKTOP-PAQ2NAV ✅ 网关配置没被重置，我方内网机器仍在映射表里 ⇒ 是"个别条目被改动"
用 Host: uav-sites / skymonitor / jsc 打 5001、8888 → 全 404 / SPA 回落 该 IP 上已无 jsc vhost
index-*.js 里搜到 /dev-api + 127.0.0.1:48080 + :1880(Node-RED) 8888 那套是 yudao / RuoYi-Vue-Plus 血统的平台 —— 与 8.11 那族同源
🔑 方法论（已沉淀进 skill）：
① 扫描一个公网 IP，得到的是「端口映射表」而不是「主机监听列表」——一个公网 IP 后面是网关 + 多台内网机， 所以"某端口关了"只能说明映射被删/后端没起，不能推"那台机器没了"。
② TLS 证书 CN 能直接认出后端真身（Windows 主机的 RDP 证书 CN = 机器名，如 DESKTOP-PAQ2NAV / DaQiServer）。 这是识别"无名端口"最快的一招。

4. ESXi 为什么也查不到

ESXi 172.16.8.24 的原有访问路径是：本机 → 226(8.12) 跳板 → sshpass 进 ESXi。 跳板那台机器的 SSH 入口已经不在（22333 易主），链路直接断掉。

另外本机 route print -4 没有任何 172.16.8.0/24 的路由，到该网段的全部连接都是 timeout， 所以 无法绕过跳板直连。全端口扫描也确认：ESXi 的 443 / 902 / 8006 未在此公网 IP 上暴露。

因此"查看 ESXi 设置"这一半任务无法完成，需要先恢复一个到 172.16.8.0/24 的入口（见下节）。
