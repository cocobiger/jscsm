1结论先行（1 分钟版）

您说的"分页和下拉框未出现"已定位根因：v5 复核页是 8/28 生成的单文件静态页，41 帧候选帧一次性全部渲染（页面 3.5MB，含内嵌缩略图），代码里没有分页、没有筛选下拉框——不是坏了，是根本没做。

现状能力盘点：判定（有烟/无烟/不确定）✓ 备注 ✓ 夜场标记 ✓ 自动保存 ✓ 统计进度条 ✓ 大图放大 ✓ 导出 JSON ✓
缺失：分页 ✗ 筛选下拉 ✗ 键盘快捷键 ✗ 沉浸式上一张/下一张 ✗ 批量判定 ✗ 未复核优先排序 ✗

核心诉求"方便标注"的瓶颈：41 张卡片堆在一条 1.2 万像素的长页面上，每标一帧要滚屏找下一张、鼠标连点 3 次，无法只看"还没标过的"，夜场帧要在长页面里翻找黄框卡片。

建议排期：3 批共约 5 小时（第 1 批 1.5h 解决"分页+下拉"痛点，第 2 批 2h 沉浸式标注提效，第 3 批 1.5h 批量+健壮性）。纯静态前端改造，无后端依赖，已标数据零丢失。

操作环节现在的体验问题等级

痛点归纳（按影响排序）

  • P0 无分页：41 帧长页 + 无页码导航，无法定位"标到哪、剩多少"；后续 400 帧全量复核时此页会直接卡死
  • P0 无筛选下拉：无法"只看未复核 / 只看夜场 / 只看已标有烟"，复查与补标全靠肉眼找
  • P1 无键盘快捷键：逐帧鼠标连点是标注效率的最大瓶颈（对标生产复检页 1/2/3 快捷键）
  • P1 大图无左右切换：lightbox 单张看图，对比相邻帧要关开两次
  • P2 批量弱、P2 渲染全量重建、P2 数据内嵌膨胀

4方案选型（A/B/C）

方案做法优点缺点结论
A 静态页原地增强（推荐） v5review.html 内加分页/筛选/快捷键/沉浸式弹层，b64 数据保留内嵌（或抽离 DATA.json） 零后端、零部署新服务；localStorage 兼容；改动集中在一个文件；已标数据不丢 数据内嵌文件仍大；刷新页面加载稍慢（41 帧可接受） ✅ 推荐
B 数据外置 + 静态页 DATA 抽到 v5review_data.json，HTML 瘦身到 <50KB，页面按需加载 HTML 极轻；后续 400 帧全量复核可行；b64 缩略图可按页懒加载 多一个文件；需处理外置读取失败回退 第 3 批并入
C 接驾驶舱后端 并入 StrawResultsView / 新增 /api/review 系列接口服务该页 与生产复检统一，天然分页/筛选 改动面大；本页是训练数据标注工具，与生产复检数据域不同（v5_candidates vs straw_detections），耦合反而乱 ✗ 不采用
选 A，第 3 批并入 B 的数据外置：符合您"长期彻底方案"偏好——一次改造，后续 400 帧全量复核不再卡。所有判定数据仍存 localStorage（LS_KEY=v5review_v1 保持不变），已标结果零丢失。

关键设计（对标生产复检页最佳实践）

  • 分页：每页 10 帧（可切 10/20/50）+ 上一页/下一页 + 页码 + 第 x/y 页，滚动位置跨页保持
  • 筛选下拉：复核状态（全部/未复核/有烟/无烟/不确定）＋ 场景（全部/白天/夜场），筛选后自动回第 1 页
  • 排序：默认"未复核优先"（已复核沉底置灰），可切按 idx
  • 沉浸式复核弹层：点击卡片进全屏大图，快捷键 1=有烟 / 2=无烟 / 3=不确定 / ←→=相邻帧 / Esc=退出，判定后自动跳下一张
  • 列表页快捷键：聚焦卡片高亮 + 1/2/3 直接判定（对标 StrawResultsView 详情弹层）
  • 批量：本页全选 → 批量有烟/无烟/不确定（对标 ServerReviewPage 批量栏）
  • 渲染：setJudge 后只更新该卡状态，不再全量重建 DOM

6冲突排查与兼容

项排查结论
localStorage 数据LS_KEY='v5review_v1' + judge 语义（smoke/no/unk）保持不变，已标 41 帧结果零丢失
nginx 静态服务:81/v5review.html 由 alias 指向 /video/llm_infer/，纯静态无后端，替换文件即生效；建议加 no-cache 头避免浏览器缓存旧版
与生产复检页关系数据域不同（v5_candidates 训练数据 vs straw_detections 生产告警），不做耦合，独立静态页改造
快捷键冲突沉浸式弹层打开时拦截父层事件（1/2/3/←→/Esc），关闭后恢复；输入框聚焦时 1/2/3 不触发
文件体积41 帧内嵌 3.5MB 可接受；第 3 批外置后 HTML <50KB，为 400 帧全量复核预留
移动端分页/筛选为响应式 flex 布局，窄屏自动换行；快捷键不可用但按钮保留

7风险与回滚

风险 1（低）：新版 bug 导致页面异常 → 备份文件 v5review_bak_20260831.html 一键还原（cp 覆盖即可）。
风险 2（低）：浏览器缓存旧版 → 部署后 nginx 加 no-cache 或用户 Ctrl+F5。
风险 3（中）：若中途想扩到 400 帧全量复核而第 3 批未做 → 内嵌 3.5MB×10 文件过大，需先完成第 3 批数据外置。
风险 4（无）：已标数据丢失 → 方案明确 LS_KEY/judge 语义不变，且改造前可先导出一次 JSON 留底。
