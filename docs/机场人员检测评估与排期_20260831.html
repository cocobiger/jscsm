1.2 与「场景过滤」的关系（关键衔接点）

⚠️ 同日评估的「场景过滤 P1-①」方案是 dock 流停秸秆推理（机场画面无秸秆意义）。本需求恰好复用同一条流做人员检测——实施顺序上，dock 流从 config.json 秸秆列表摘除的同时，dock-guard 服务接管该流，一鱼两吃，不冲突、不浪费。

二、方案设计

2.1 核心思路：独立 dock-guard 服务（职责单一，不碰秸秆主线）

维度设计理由
服务形态独立 Python 服务 dock-guard.service（systemd，多线程每机场一路）不动 straw-engine，零风险；与秸秆推理可独立启停/升级
检测模型复用 yolov8s.pt，只跑 classes=[person]，imgsz 960机场画面人小（广角+高空），960 输入已实测有效；GPU 推理单帧 <50ms
ROI 布防区每机场一个多边形 ROI（停机坪+舱门区域），只统计人框中心点落入 ROI 的检测机场固定机位，画面恒定；镜头边缘路人不误报
防误报三板斧①连续 3 帧命中（帧间隔 1s，≈3s 确认）②告警后 60s 冷却 ③人形尺寸过滤（高度占比 2%~60%）人不会瞬时消失；同人反复触发只告一次；飞鸟/影子/远处汽车排除
告警接入POST /api/straw-alert，aiType='机场人员入侵'，source='dock-guard'，带 bbox+带框截图复用入库/定位/前端展示全链路，零后端新接口
布防配置每机场独立：启停开关、ROI 坐标、置信度阈值、布防时段（默认全天）、夜间高敏开关运维灵活：调试点位、作业时段可单独撤防

2.2 检测逻辑（worker 循环）

循环（每机场线程，间隔 1s）: 1. 从 ZLM 拉流取帧（FLV/RTSP → cv2） 2. YOLOv8s 全画面检测，过滤出 person 类（conf≥阈值） 3. 人框中心点 ∈ ROI 多边形？ → 命中 4. 连续命中计数 ≥ 3 → 触发告警： - 截带框图 → 存 /api/evidence 目录 - POST /api/straw-alert {aiType:'机场人员入侵', label:'person', confidence, bbox, imageUrl, streamId, sensor:'visible'} 5. 冷却 60s 内不再重复告警（人仍停留则每 60s 补报一次，可配置）

三、方案对比（A/B/C）

方案形态优点缺点判定
A 独立 dock-guard 服务 新 systemd 服务 + 复用 venv/模型 职责单一、零影响秸秆主线、独立启停/升级、ROI/冷却策略可自由扩展 多一个进程（GPU 显存 +~1.5GB，3090 充裕） 推荐 长期方案，契合「彻底隔离」惯例
B 并入 straw-engine 在 main.py 加 dock 分支 省一个进程、复用现有 worker 框架 耦合两套检测逻辑；场景过滤 P1 要停 dock 秸秆推理，同文件改两处易错 不推荐
C 后端 Node 定时截图检测 jsc-backend 内 setInterval 拉截图调 ONNX 最轻量、无新服务 Node 侧无现成 YOLO 推理环境；帧率低（秒级 1 帧）；GPU 复用难 不推荐

五、冲突排查（已逐项核对）

潜在冲突核查结论
dock 流被场景过滤 P1 停掉？不冲突：P1 停的是「秸秆推理」，dock-guard 接管后该流继续被消费（人员检测），画面/流本身不动
与秸秆告警抢 GPU？3090 24GB：秸秆引擎 + dock-guard 各自 <2GB，显存充裕；推理时延均远低于帧间隔
夜间干扰多？人员检测与秸秆不同：人形轮廓在夜间红外/补光下仍可检；布防时段默认全天，夜间可单独调阈值
机场作业人员误报？布防时段配置（如维护时段撤防）+ ROI 划定（只圈停机坪不圈出入口）+ 冷却；误报可接受度由阈值调
与司空自带的机场防护功能重复？司空有周界/降落保护，但归属司空平台（web 界面），我方驾驶舱要的是本地自主预警；二期可考虑调司空 API 联动锁舱（见 D5）
后端零改动？是：/api/straw-alert 为 PUBLIC 接口，aiType 传「机场人员入侵」即可入库展示；仅前端按新 aiType 加样式（新2）

六、风险与回滚

风险清单

风险等级缓解
dock 流当前不在线（夜间无任务），联调需等流中新1 开发期用历史录像/模拟流验证，真机联调排到白天作业时段
人员误报（影子/动物/树叶晃动）中3 帧连续确认 + 尺寸过滤 + ROI，实测调阈值
ROI 划错导致漏报（人没进框）低ROI 支持热更新，划框页实时预览帧 + 试触发
告警风暴（多人/持续停留）低60s 冷却 + 每机场每日告警上限（可配）

回滚方案

dock-guard 为独立服务，systemctl stop dock-guard 即整体撤防（不碰秸秆主线）；配置热重载失败自动回退上一版 config.json；前端样式改动仅影响新 aiType 展示，不影响既有告警。
