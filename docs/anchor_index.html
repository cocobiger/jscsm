STEP 1
轻烟判定与标注协议 v1.2
先读这份。尺度分档、5 步判定流程、五档判定（含明火/明火+烟）、易混淆清单、画框规则、一致性门禁。不读协议直接标等于白标。
STEP 2
锚点确认工作台（39 张）
两位标注员各自独立标注：五档判定 + 尺度档 + 理由码。含内置一致性校验与导出/导入进度。

怎么用（3 步）

  1. 先读协议 —— 点左边那张卡。重点看 §3 判定流程 与 §4 判定档口径（五档）。
  2. 两名标注员各标一遍 —— 打开工作台，右上角切到「标注员 A」或「标注员 B」， 两人请互不通气，各自把 39 张都填完（每张要选：五档判定 + 尺度档，理由码尽量选）。
  3. 点「一致性」看结果 —— 页面右下角会弹出面板，给出两项指标与 PASS/FAIL。 同时点「导出 A+B」把 JSON 存下来交回。
放行门槛：粗口径一致率 ≥ 80% 且 尺度档一致率 ≥ 80%（两项都是硬门槛）。
粗口径 = 焚烧 / 疑似 / 非焚烧三分类 —— 即 v1.2 起把「确定烟 / 明火+烟 / 明火」先合并为「焚烧」再比对。 门禁只问"烧没烧"；五档细口径（能区分出是纯烟还是明火）只作参考、不卡门禁 —— 否则两人「都认定在烧、只是对火烟成分看法不同」会被误判成口径失守。
达标即可开始正式标注；未达标不要开标注——先针对粗口径分歧最大的几张把口径谈清楚（协议升版）再重测。
v1.2 新增了「火」档，为什么？ —— 秸秆焚烧夜间常先见火光、后起烟， 原来的「确定烟 / 疑似轻烟 / 非烟」三级装不下"有火"这件事；标成"非烟"会让模型学错， 标成"确定烟"又掩盖了火的证据。所以拆成五档：
档位什么时候选
明火+烟画面里同时能看到明火/亮核 和烟柱（最常见于起燃阶段、夜间）
明火只有明火/亮核，看不到明显烟
确定烟有明确烟柱，看不到火（多见于燃烧中后段、白天）
疑似轻烟像烟但太淡/太小/太远，拿不准（宁可选这个，别硬判）
非烟确定的云、扬尘、水汽、反光、近场机场本体等
三档火/烟的选择本身不影响门禁（都算"焚烧"），但对下一轮训练数据有直接价值 —— 别随手乱选。

两个重要提醒

① 进度存在本机浏览器里（按「标注员 A / B」分开存），关掉页面不会丢，可随时中断续做。
若你要换电脑或换浏览器：先在原机器点「导出 A+B」存成 JSON，到新机器打开本页 → 点「导入进度」选那个 JSON → 就能接着标。
② 页面刻意不显示"程序算出来的档位和亮度"。这是故意的 —— 一旦给了提示， 两人的一致性数据就失真了，这次校准就白做了。只看图判断。

为什么要先做这一步

背景说明
要解决的问题 现网模型对"远方轻烟"（等效边长 < 40px）几乎没有召回——因为它的训练集里 1041 个框中小于 40px 的只有 18 个（1.7%），模型从没见过这种目标。
所以要补数据 要按"尺度档 × 昼夜"把远烟样本补上来，目标：<40px 占比提到 15–20%。
但先要对齐口径 "多远算远、多淡算轻"如果两人理解不同，标出来的标签就是噪声，而且不可逆。 所以先用 39 张锚点样本把两人的判定口径校准到一致。
本次锚点覆盖 D(远) 白天 12 / 夜间 0 ｜ M(中) 白天 12 / 夜间 2 ｜ N(近) 白天 12 / 夜间 1
顺带说明：筛选锚点时发现 夜间的小目标样本几乎为零（D 档夜间 0 张，夜间小目标总数只有 5 个）。 这意味着"夜间远烟"目前没有数据可用，需要专门安排夜航采集/标注。这一点会在下一轮排期里单独处理。

交回什么

  • 两人各自的导出 JSON：anchor_annot_v12_A.json / anchor_annot_v12_B.json（或一份 anchor_annot_v12_both.json）
  • 若能顺便记录：两人各自觉得"最难判"的 3 张是哪几张，以及卡在哪（这比指标更有用）

收到的 JSON 会用配套脚本复核归档：

python check_agreement.py anchor_annot_v12_A.json anchor_annot_v12_B.json
# 或（合并导出）
python check_agreement.py anchor_annot_v12_both.json
