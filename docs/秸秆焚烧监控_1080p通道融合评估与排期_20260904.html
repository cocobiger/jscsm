一、需求与关键发现

需求：把遥控器录像（1080p，准实时延迟 6-9 分钟）接入现有「秸秆焚烧监控」检测链，自动抽帧→检测→生成秸秆燃烧事件；并与现有「实时直播流检测」融合，避免功能冲突。

今日真飞实证（数据已落盘）：

通道分辨率延迟检测灵敏度（E1 结论）状态
司空 mirror 直播流1280×720（960~1280 宽）秒级远烟全盲（stage2 三档 IoU 命中恒 0，弱检出全为背景误检）已部署
遥控器录像（dock_media）1920×1080（另有 4K/红外档）6~9 分钟像素多 2.25 倍，远烟/小目标可辨识度质变（待离线验证量化）取样闭环已通
核心判断：两条通道不是冲突，而是互补——720p 是「秒级快筛」，1080p 是「分钟级精筛」。这正是告警检测领域的标准两级架构（实时发现 + 延迟复核）。真正要做的是把「互补」落地成「去重合并 + 统一事件模型」，而非二选一。

三、功能冲突点仔细梳理（逐项）

冲突维度现象等级解法
① 重复告警同一烟事件，720p 实时通道（可能漏）与 1080p 延迟通道（晚 6-9min）先后各报一次 → 驾驶舱看到两个事件P0事件合并键 = 无人机SN + bbox 反投影地理坐标 + 15min 时间窗；1080p 命中已有事件 → 升级/补充（附 1080p 证据）而非新建
② 时序错位720p 秒级 vs 1080p 延迟 9min，Confirmer 连续 3 帧在录像上意义不同P1两通道独立 Confirmer（已按 streamId 隔离）；录像抽帧对齐 2s 间隔，连续帧确认仍有效
③ GPU 资源720p 6 worker 全 CUDA 常驻 + 1080p 检测若也上 GPU → 显存/算力叠加P11080p HEVC 解码用 CPU（已实测）；检测 onnx 复用 GPU 但限并发/错峰（当前 3090 空闲 19G，6 worker 检测时 util 低）；必要时 1080p 检测降频
④ 训练域差异模型 v5 stage2 训练图是 720p（960×720/1280×720）；1080p 输入细节更多，域迁移效果未验证P1段 1 先做「1080p 帧离线喂检测器」量化增益（G1）；增益为正才推进
⑤ 源状态语义config streams 目前全是「直播流」，1080p 是「文件源」——打开/重连语义不同P2config 加 source: 'file'|'live' 字段，worker 分支处理
⑥ 夜判/OSD录像非实时，OSD 起飞窗口跳过逻辑可能误伤录像帧P21080p 文件源关闭 OSD skip（录像无起飞画面），夜判保留
结论：唯一硬冲突是 ① 重复告警（需后端合并去重）；其余均为「工程适配」而非「功能冲突」。融合完全可行，且当前架构（streams 数组 + 分类别阈值 + 统一 /api/straw-alert）天然支持多通道扩展。

四、融合方案设计（两级检测架构）

统一事件模型：所有告警带 channel（mirror 720p 实时 / dock1080 准实时）+ 原 streamId + bbox + 置信度。后端合并键按「SN + 地理 + 时间窗」聚合。

方案做法推荐度
A（推荐）
双通道互补		 720p 实时通道保持现状（秒级发现）；1080p 通道媒体归档后自动抽帧→检测→上报（channel=dock1080）；后端合并去重（1080p 命中已有事件=升级证据）。告警列表显示通道标签，同一事件可回看 720p 实时 + 1080p 高清双证据 推荐
B
1080p 独立事件		 1080p 通道完全独立上报，不与 720p 合并（会重复告警，仅当「不同地点」才有意义） 不推荐
C
1080p 仅取证不上报		 1080p 只做「告警后取证」（720p 报了→自动拉 1080p 高清帧附证据），不独立触发检测/告警 保守备选

推荐 A：兼顾「1080p 能检出 720p 漏掉的远烟」（补召回）+「同一事件不重复」（合并去重）。C 作为 A 的第一阶段可先行（先取证后独立检测）。

七、结论与决策点

① 现有功能点已梳理（引擎 10 项 + 前端 15 项 + 后端 3 项），架构天然支持多通道；② 冲突唯一硬点是重复告警（后端合并去重可解），其余为工程适配；③ 融合可行且互补（720p 秒级快筛 + 1080p 分钟级精筛两级检测）；④ 排期 4~5 天，G1 为增益闸门。

决策点：① 方案选 A（双通道互补+合并，推荐）／ C（1080p 仅取证）？② 是否先跑 G1 离线增益验证（0.5 天，决定 1080p 是否独立检测）？③ G2 后端合并去重是否立即并行开工？

8.3 G1 闸门启示 + 方案调整为 C

为什么 1080p 救不了？瓶颈在模型，不在输入：
  1. 训练域缺口：v5 stage2 训练图来自 720p 司空 mirror（城区/工厂视野），对 9/2 山坡远烟（域外）学得不够
  2. imgsz 硬限：onnx export 锁 1280×1280，4K 输入 letterbox 缩到 1280，关键小目标细节被压缩
  3. E1 已证同根：720p live_review 182 帧 IoU 命中恒 0 → 不是像素问题是模型能力问题
1080p/4K 仍有的价值（与检测无关）：
  • ✅ 取证清晰度：告警后人眼确认、看烟形/位置（7.4MB 单帧 vs 100KB 720p）
  • ✅ 训练样本：49 张 yes 帧可直接进 v54 治理工作台做训练正样本
  • ✅ 复检精度：ServerReviewPage 显示 1080p 帧，人工复核置信度更高
  • ✅ 事后留档：客户/取证/法律用途的清晰证据
方案调整为 C（推荐）：1080p 仅取证不检测——告警触发后自动拉 1080p 录像帧附在告警详情（不独立触发新告警）；不需后端合并去重（无重复告警风险）；不需 v54 重训后再启用；零额外模型负载。
