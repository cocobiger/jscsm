「VLM 提示 + YOLO 框体标注」技术思路评估
—— 无人机实时视频流检测的新思路可行性分析
编制时间：2026-09-08评估方式：技术原理 + 现有资产核对性质：思路可行性评估（未实施）

一、结论摘要

思路方向有启发价值，但「VLM 用文字提示让 YOLO 画框」这一核心环节存在技术错位，字面意思上不可行。

核心原因：普通 YOLO（v8/11）是"图像→框"的端到端检测器，不接受文字提示，无法"按照 VLM 的语言描述"去定位目标。VLM 的文字描述（"左上方远方有淡淡烟柱"）是语义化的、无法直接转成精确像素框。

但这个思路里有价值的部分可以改造成几个可行的替代方案（见第四节）。

二、思路拆解与逐环节技术判断

用户的思路可拆成 4 个环节：

环节可行性技术事实
① VLM 看视频流判断"有真烟"可行但有硬伤VLM 能看图像判断烟（已有 qwen2.5vl:7b 在跑二分类）。但 VLM 推理秒级，视频流 25-30fps，无法"实时"，只能抽帧异步判断
② VLM 输出文字提示（"左上方远方有淡烟柱"）可行VLM 天然能输出语义描述（现有 vlm_smoke_judge_tf.py 的 reason 字段就是"右侧山丘冒白烟柱"）
③ 抽帧出图可行已有抽帧能力（straw-engine interval 抽帧）
④ YOLO 按 VLM 文字提示做框体标注❌ 不可行（核心错位）普通 YOLO 是端到端检测器，输入是图像、输出是框，不接受文字 prompt。它要么自己检出烟并出框，要么检不出——VLM 的文字描述无法"喂给" YOLO 让它定位

核心错位：YOLO 本身就是一个"图像→框"的检测器，它出框靠的是自己在图像上做 dense 预测，不依赖、也无法利用外部文字提示。如果 YOLO 已经检不出远处的烟（这正是当前 v5 stage2 的问题），VLM 说"左上方有烟"也不能让 YOLO 凭空画出那个框——VLM 的语言描述无法转换成 YOLO 可执行的定位指令。

三、为什么"文字提示驱动 YOLO"不成立

3.1 模型本质不同

模型输入输出能否用文字定位
YOLOv8/11（检测）图像固定类别框（xyxy+conf+cls）不能（不接受文字）
YOLO-World / Grounding DINO图像 + 文字 prompt框能（open-vocabulary 检测，可"按烟"检测）
Qwen2.5-VL（grounding 版）图像 + 文字可直接输出框坐标能（但精度/实时性差）

关键：如果目标是"用文字/语义驱动定位"，正解是 open-vocabulary 检测模型（YOLO-World、Grounding DINO）或 带 grounding 的 VLM，而不是"VLM 描述 + 普通 YOLO"的组合。普通 YOLO 无法理解 VLM 的文字。

3.2 项目现有 VLM 不支持框输出

现有 `qwen2.5vl:7b`（ollama）+ `model3b`（transformers）都只做文本二分类（输出 verdict/confidence/reason），不输出框坐标。ollama 的 qwen2.5vl 也不支持 grounding 坐标输出。所以要实现"VLM 直接出框"，还需换模型/换推理方式。

四、可行的替代方案（思路的价值重构）

用户思路里真正有价值的是「用 VLM 补足 YOLO 对远烟的召回盲区」。可改造成以下方案：

方案做法评估
A：VLM 复核（降误报） YOLO 出一堆候选框 → 对每个框裁图喂 VLM 判"真烟/假烟" → 过滤误报 解决误报，不解决召回 YOLO 没检出的框 VLM 看不到，远烟仍漏检
B：VLM grounding 直接出框（绕开 YOLO） 用带 grounding 的 VLM（Qwen2.5-VL 原版 grounding token / GLM-4V / InternVL）直接输出烟框坐标 理论可行 但 VLM 定位精度差（远烟小目标）、秒级推理不实时、需换模型部署
C：open-vocabulary 检测（YOLO-World/Grounding DINO） 用支持文字 prompt 的检测模型，直接 prompt "smoke" 检测出框 方向最正 本质是"更强的检测模型"，但训练/部署成本高，且对远烟小目标效果待验证
D：VLM 弱监督 + 人工框（训练数据） VLM 判断有烟 → 人工在图上框 → 回流训练集（正是现有 v54 治理流程） 已在做 这是长期治本：补足训练域缺口，让 YOLO 下次能检出远烟

五、与现有系统的关系

项目现状（记忆已沉淀）：

① v5 stage2 对 DJI 远烟零检出——根因是"模型能力瓶颈"（训练域缺远烟样本），不是阈值/像素问题（G1 闸门、E1 快评、段2续训三次失败均已证实）。

② VLM 已在做方案 D——qwen2.5vl 用于离线数据预筛，判断误标框复用为 hard negative（v54 治理流程）。

③ 所以用户这个思路，本质是想绕开"重训 YOLO"用 VLM 实时补足远烟检测。方向可以理解，但"VLM 文字提示 + 普通 YOLO 画框"的组合在技术上不成立，需换成上面 A/B/C 之一。

六、结论与建议

① 字面思路不可行：普通 YOLO 不接受文字提示，"VLM 描述 → YOLO 按提示画框"是技术错位；

② 思路价值可重构：真正要做的是"用更强的检测能力补足远烟召回"，对应方案 B（VLM grounding）/C（open-vocabulary 检测）/A（VLM 复核降误报）；

③ 长期治本仍是方案 D：VLM 预筛 + 人工框回流训练集，补足远烟训练域，让 YOLO 自身能力提升——这是项目已在走的路；

④ 若明天就要验证：不建议临时上 VLM 实时检测（秒级延迟 + 定位精度差 + 需换模型），建议按现有 YOLO 链路 + 低空近烟场景先验链路贯通性，远烟召回问题走方案 D 长期解决。

本报告基于 2026-09-08 技术原理评估 + 现有资产核对（qwen2.5vl:7b ollama + model3b transformers，均只做文本二分类不支持框输出）。未实施任何改动。如需落地某个替代方案（B/C/A），需另做技术选型与排期。
