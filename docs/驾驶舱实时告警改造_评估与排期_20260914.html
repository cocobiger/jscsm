一、需求评估（业务价值 + 设计原则）

1.1 核心诉求

把驾驶舱首页的「实时告警」从 静态信息列表 重做成 专业预警中枢，让大屏值班人员/应急指挥在 3 秒内 完成：

  1. 看见：哪些告警是秸秆类（带火焰红标 + 现场实景图 + 置信度）
  2. 定位：发生在哪个机场 / 哪个镇街 / 经纬度（鼠标悬停出地图）
  3. 判断：是真烟还是误报（连续帧确认 + 置信度 + bbox 可视化）
  4. 处置：直接标"有效·转处置"或"误报·标记"（闭环到秸秆样本库）

1.2 设计原则（从秸秆专项提炼的可复用要素）

1.3 与秸秆专项的差异（驾驶舱独有）

  • 大屏化：驾驶舱用于值班大屏 / 领导汇报；秸秆专项是管理后台精细操作。驾驶舱要"一眼可读"，秸秆专项要"可点可配置"
  • 多源融合：驾驶舱同时显示 IoT 视频分析（堆头未覆盖等）+ 秸秆 + 气体。秸秆专项只看 straw
  • 实时性优先：驾驶舱 10s 轮询要"新告警突出显示 + 提示音 + 滚动定位"；秸秆专项不在意这个
  • 不要破坏现有体验：当前实时告警列表是用户最常用的入口（"看告警 → 点详情 → 处置"），改造要保留核心路径不换皮

五、决策点（请拍板）

5.1 范围选择

  1. 最小可用版（P0 + P1，~2.5d）：副标题升级 + 处置闭环 + 火焰红标。值班人员可"看 + 判 + 处置"，但不带框流。→ 推荐起步
  2. 完整版（P0~P4，~6d）：含带框流弹窗 + 大屏化。最贴近秸秆专项的体验
  3. 分两期：先 P0+P1 上线（本周）；下周排 P2~P4

5.2 待用户确认项

  1. 驾驶舱的"实时告警"是否要新增"处置按钮"？处置动作在驾驶舱上做 → 风险是误操作（值班不小心点了"误报"会污染样本库）。是否需要二次确认？是否限制仅操作员（operator）角色？
  2. 置信度阈值：现网 0.15（秸秆 15%）也在告警列表里。要不要在驾驶舱低于 0.3 的告警默认折叠（不破坏秸秆专项判定）？
  3. 缓存修复：用户截图里的 "null" 是浏览器缓存所致，请刷新一次驾驶舱首页确认 channelName 已是「三峡科技机场」，再开始排期
  4. 责任人维护：如果新增「驾驶舱可见责任单位」，需要用户补全责任人姓名/电话（area_responsibility 表里目前 0 行，从秸秆专项抽样 9/3 数据看有 2 条）—— 是否补一批？
