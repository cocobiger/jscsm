# 重庆移动云MAS 短信对接说明

> 适用模块：管理后台「短信预警推送 → 云MAS配置」
> 后端实现：`server/sms-mas.js`
> 协议方式：**HTTP（普通短信提交 norsubmit）**

---

## 一、为什么选 HTTP 协议

在移动云MAS 平台申请短信接口时，「协议」一项请选择 **HTTP**。

本系统后端 `sms-mas.js` 实现的是 MAS 平台的 HTTP 普通短信提交接口：将一组参数组装成 JSON，计算 MD5 签名（mac），整体做 Base64 编码后，以 HTTP POST 方式提交到平台网关。这与平台下拉中的「HTTP」协议一一对应。

各协议选项对照：

| 平台协议选项 | 是否选用 | 说明 |
| --- | --- | --- |
| **HTTP** | ✅ 推荐 | 明文 HTTP 接口，本系统直接支持，`masUrl` 填 `http://...` |
| HTTPS | ⭕ 可选 | 网关强制 TLS 时选用，`masUrl` 填 `https://...`，代码自动兼容 |
| CMPP2.0 / CMPP3.0 | ❌ | 运营商级长连接协议，需专用 socket 客户端，本系统不支持 |
| SDK2.0 / NETSDK | ❌ | 需移动提供的 SDK 包对接，本系统不走此方式 |
| HTTP-M1 / WS / AIC / BDM | ❌ | 特定场景变种，普通短信提交用不上 |

平台申请页其它选项建议：

- **回执状态**：选「需要回执 / 开启」，便于获取送达状态（不影响发送）
- **接口状态**：选「启用 / 有效」
- **安全认证**：与「协议」保持一致（选 HTTP 对应认证方式）

## 二、平台字段 → 系统配置对应关系

接口申请通过后，移动云MAS 平台会下发一组账号参数。将它们填入管理后台「短信预警推送 → 云MAS配置」对应输入框即可。

| 管理后台输入框 | 后端配置键 | 平台下发字段（常见叫法） | 说明 | 是否必填 |
| --- | --- | --- | --- | --- |
| 网关地址 (masUrl) | `masUrl` | 短信提交地址 / 接口URL / API地址 | 普通短信提交接口完整 URL，形如 `http://网关IP:端口/sms/norsubmit` | 必填 |
| 集团名称 (ecName) | `ecName` | 集团名称 / 企业名称 / 客户名称 | 在 MAS 平台注册的集团/企业全称 | 必填 |
| 接口账号 (apId) | `apId` | 接口账号 / API账号 / 应用ID | 平台分配的接口登录账号 | 必填 |
| 接口密码 (secretKey) | `secretKey` | 接口密码 / API密码 / 密钥 | 平台分配的接口密码，参与 mac 签名计算 | 必填 |
| 签名编码 (sign) | `sign` | 签名编码 / 短信签名码 / 签名ID | 平台申请的短信签名标识，如 `zHsmzt`（**不是**中文签名本身） | 必填 |
| 拓展码 (addSerial) | `addSerial` | 拓展码 / 扩展码 | 通道拓展码，无则留空 | 可选 |

> **secretKey 安全说明**：出于安全，配置保存后接口密码不会回显。再次编辑时该框留空表示「保持原密钥不变」，只有重新输入才会覆盖。

## 三、HTTP 请求结构（后端自动完成，仅供排错参考）

### 3.1 请求方式

```
POST  {masUrl}
Content-Type: application/json;charset=UTF-8

Body：Base64( JSON字符串 )
```

### 3.2 Base64 编码前的 JSON 字段

| JSON 字段 | 取值来源 | 说明 |
| --- | --- | --- |
| `ecName` | 配置 ecName | 集团名称 |
| `apId` | 配置 apId | 接口账号 |
| `secretKey` | 配置 secretKey | 接口密码（部分网关要求 body 中留空，见下方兼容说明） |
| `mobiles` | 联系人手机号 | 多个号码用英文逗号 `,` 拼接 |
| `content` | 模板渲染结果 | 短信正文（不含签名，签名由平台拼接） |
| `sign` | 配置 sign | 签名编码 |
| `addSerial` | 配置 addSerial | 拓展码，可为空字符串 |
| `mac` | 自动计算 | 见下方签名算法 |

### 3.3 mac 签名算法

```
mac = MD5( ecName + apId + secretKey + mobiles + content + sign + addSerial )
```

- 按上述固定顺序直接字符串拼接（无分隔符）
- 取 32 位小写十六进制 MD5 值
- `addSerial` 为空时拼接空字符串

> **secretKey 兼容开关**：部分省份网关要求「secretKey 参与 mac 计算，但提交 body 中 secretKey 字段留空」。后端 `keepSecretInBody` 选项控制这一行为，默认 `true`（保留），适配多数网关。若平台返回签名/认证类错误，可在后端配置中将其设为 `false` 重试。

### 3.4 平台返回判定

平台返回 JSON，后端按以下规则判定受理成功：

- `success === true`（或字符串 `"true"`）
- 或 `rspcod === 'success'`
- 或 `rspcod === '0000'`

满足任一即视为「平台已受理」，记录为成功；否则记为失败并保留平台返回的 `rspcod` / `msg` 供排错。

> 注意：「平台受理成功」表示短信已提交到运营商，最终送达状态需通过回执接口或平台报表查看。

## 四、短信内容模板与变量

在「短信模板」页编辑模板内容，支持以下变量（发送时自动替换为实时数据）：

| 变量 | 含义 | 示例值 |
| --- | --- | --- |
| `{point}` | 监测点位名称 | 周家坝监测站 |
| `{pollutant}` | 污染物名称 | PM2.5 |
| `{value}` | 当前监测数值 | 86 |
| `{unit}` | 数值单位 | μg/m³ |
| `{label}` | 预警类型 | 跨阈值预警 |
| `{time}` | 监测时间 | 2026-06-09 10:00 |

模板示例：

```
【生态环境预警】{point} {time} 监测到 {pollutant}={value}{unit}，触发{label}，请及时关注处置。
```

渲染后：

```
【生态环境预警】周家坝监测站 2026-06-09 10:00 监测到 PM2.5=86μg/m³，触发跨阈值预警，请及时关注处置。
```

> 短信签名（如【某某环境局】）由 MAS 平台根据 `sign` 自动拼接，模板内容**无需**再写签名。

## 五、自动推送触发与频率限制

- **触发条件**：空气质量采集数据命中预警规则（PM2.5/PM10/SO₂/NO₂/O₃/CO 超标），自动向全部「启用」状态的联系人推送短信。
- **频率限制**：同一「点位 + 污染物 + 预警类型」组合，在 **30 分钟**内只发送一次，避免重复轰炸。窗口由后端 `SMS_DEDUP_WINDOW_MS` 控制。
- **模板选择**：优先使用触发类型为「空气质量超标(air)」且启用的模板；否则取第一个启用模板。
- **未配置时**：若 MAS 未配置完整或无启用联系人，自动推送静默跳过，不影响采集主流程。

## 六、模板短信（tmpsubmit）

除了普通短信（自由内容），系统也支持**模板短信**——在云MAS 平台报备审核通过的模板，发送时只传模板ID和变量值，由平台拼接成短信。

> **何时用模板短信**：如果你的签名/账号被限定只能发已审核模板（普通短信被平台拒），就需要走这条路。你的签名类型标注为「模板短信」，因此这是重要备用通道。

### 6.1 平台侧准备

1. 登录云MAS 平台 →『短信』→『模板短信』→『模板管理』，创建模板并提交审核。
2. 模板里用平台的变量占位（平台自己的格式，**不是**系统的 `{point}`）。
3. 审核通过后获得 **模板ID（templateId）**。

### 6.2 系统侧配置

管理后台「短信预警推送 → 短信模板」页，新增/编辑模板时：

- **短信类型**：选「模板短信（走 tmpsubmit）」
- **平台模板ID**：填上一步拿到的 templateId
- **变量字段顺序**：逗号分隔，指定发送时按什么顺序从预警数据取值填入平台模板的变量位。可选字段：`point`（点位）、`pollutant`（污染物）、`value`（数值）、`unit`（单位）、`label`（预警类型）、`time`（时间）。
  - 例：平台模板是「{1}监测到{2}超标，数值{3}」，则变量字段顺序填 `point,pollutant,value`
- **短信内容**：模板短信模式下此字段仅用于本地预览和历史留痕，实际内容由平台模板生成。

### 6.3 HTTP 接口差异

| 项目 | 普通短信 | 模板短信 |
| --- | --- | --- |
| 地址 | `/sms/norsubmit` | `/sms/tmpsubmit` |
| 关键字段 | content（短信正文） | templateId + params（变量数组） |
| mac 拼接顺序 | ecName+apId+secretKey+mobiles+content+sign+addSerial | ecName+apId+secretKey+**templateId**+mobiles+**params**+sign+addSerial |
| params 格式 | — | 字符串化数组 `["值1","值2"]`，无变量填 `[]` |

> 注意：params 在 mac 计算串里引号**不转义**（如 `["abcde"]`），在 JSON body 里引号**需转义**。系统已自动处理，无需手动干预。

模板地址默认由网关地址自动推导（`norsubmit` → `tmpsubmit`），也可在配置中单独指定 `tmpUrl`。

## 七、黑名单与失败重试

### 7.1 黑名单

管理后台「短信预警推送 → 黑名单」页可管理黑名单号码。

- 黑名单中的号码在**所有发送**（自动预警 + 手动群发）时都会被过滤，不会收到短信。
- 被过滤的号码记入发送历史的 `blocked` 字段。
- 若收信人全部在黑名单中，发送跳过并提示。
- 存储于 `server/data/sms_blacklist.json`。

### 7.2 失败重试

发送失败时系统按错误类型区别处理：

- **网络类失败**（请求超时、连接错误、HTTP 5xx）：自动重试，默认 **2 次**、间隔 **1.5 秒**。
- **平台业务拒绝**（`IllegalMac`/`IllegalSignId`/`InvalidUsrOrPwd`/`NoSignId`/`TooManyMobiles`/`NOT_WHITE_IP`）：**立即停止不重试**（重试无意义，需修配置）。
- 重试次数记入发送历史的 `attempts` 字段。
- 重试参数可在后端配置 `retryCount`、`retryDelayMs` 调整。

## 八、配置步骤清单

1. 在移动云MAS 平台申请短信接口，**协议选 HTTP**，记录下发的 ecName / apId / secretKey / sign 及网关地址。
2. **将服务器公网 IP 加入平台接口白名单**（否则返回 `NOT_WHITE_IP`）。查公网 IP：`Invoke-RestMethod -Uri "https://myip.ipip.net"`，然后在平台接口账号设置里填，或找客户经理添加。
3. 管理后台「短信预警推送 → 云MAS配置」填入参数，点「保存配置」。**注意：含中文的 ecName 务必用管理后台 UI 填写**（浏览器 UTF-8 正确），不要用 PowerShell（会把中文变问号导致 IllegalMac）。
4. 点「测试网关连通」确认网关可达（仅探测网络，不实际扣费）。
5. 「联系人」页添加接收人手机号，确认状态为「启用」。
6. 「短信模板」页确认有一个启用的模板（系统已内置默认普通短信模板；如需模板短信见第六章）。
7. 可在「发送历史」页用「手动群发」发一条测试短信，验证账号有效性。
8. 之后空气质量超标会自动按模板推送给启用联系人。

## 九、常见返回错误排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 提示「云MAS 短信未配置完整」 | ecName/apId/secretKey/sign 有缺失 | 补齐四项必填参数 |
| `NOT_WHITE_IP` | 服务器公网 IP 不在平台白名单 | 查公网 IP，在 MAS 平台或找客户经理加入接口白名单 |
| `IllegalMac` | mac 签名错（常见：ecName 中文编码损坏，如用 PowerShell 发送变成问号） | 用管理后台 UI 重新保存配置（浏览器 UTF-8 正确） |
| `InvalidUsrOrPwd` | apId 或 secretKey 错误 | 核对账号密码 |
| `IllegalSignId` / `NoSignId` | 签名编码错误，或账号限定模板短信 | 核对 sign；若限定模板短信，改用模板短信模式（见第六章） |
| `IllegalMessage` / 模板相关 | 普通短信被拒，账号可能只允许模板短信 | 改用模板短信（tmpsubmit） |
| 「MAS 网关连接超时」 | masUrl 地址/端口错误，或网络不通 | 核对网关地址，确认服务器能访问该 IP:端口 |
| 平台受理成功但手机未收到 | 签名未报备、内容含敏感词、号码黑名单 | 查平台报表与回执；核对签名报备状态 |
| 手机号格式错误 | 非 11 位 1 开头号码 | 检查联系人手机号 |
| 收信人全部被过滤 | 号码都在系统黑名单中 | 检查「黑名单」页 |
