1. 目的与适用范围

本协议解决一个具体问题："远方轻烟"没有公认的判定标准，多人各标各的，标签会变成噪声且不可逆。

因此本协议只做一件事：把"轻烟"变成可复现、可校验的判定动作。凡是本协议未覆盖的情形，一律进入 疑似 或 挂起，不允许自由发挥。

适用说明
适用无人机巡检可见光帧（4 机场 sikong_* 流）、驾驶舱取证图；昼/夜均适用
不适用红外/热成像、非本项目相机来源的图片（如外部公开数据集、社交平台转发图）——混入会教错外观
不采集SIM_SMOKE / 机场直连流 / 机库盖子视角（项目铁律：禁入训练集）

2. 尺度分档定义（为什么这么分）

分档按 等效边长 @1920 计算，与训练/推理口径一致：

等效边长 = sqrt(wnorm × hnorm) × 1920   （w/h 为归一化框宽高；若源帧非 1920 宽，先按 letterbox 缩放到 1920 再折算）
档位等效边长含义与典型表现
D（远）< 40 px 本项目要攻的目标档。远处一抹淡淡灰白，边界模糊、无明显羽状结构；常只有十几个像素，需要放大才看得出"在动"。
M（中）40 – 160 px 能看出烟柱轮廓与上升方向，仍可能与云/雾混淆。当前模型的主战场。
N（近）> 160 px 烟柱结构清楚、有明确源点（田块/垃圾堆）。
为什么必须分档报告——实测数据说明问题
现网白天/夜间两个模型同训自 v5_train_v5，该集 1041 个框的等效边长分布： p05=54.2 · p50=140.7 · p90=383.2，其中 <40px（D 档）仅 18 个、占 1.7%。
⇒ 模型从未见过 D 档，这正是"降阈值也救不回召回"的根因。所以本次标注的首要目标是把 D 档样本补上来， 而不是再去堆 N 档的大烟。

3. 判定流程（5 步，严格按顺序）

1
看连续帧，不看单帧。调出该点位的连续 5–10 帧（时间上相邻，间隔按抽帧率）。
单帧无法区分"轻烟"与"一小块碎云"——判别信息在时间维度： 烟会缓慢上升、向外扩散、形态连续演化；云整体漂移、形态基本稳定、边界相对锐利。
2
查接地/近接地（最高优先级的先验）。秸秆焚烧的烟必然源于地面。
  • 框的下沿是否触及或紧邻地表/地平线附近的地物（田块、坡地、建筑、林带）？
  • 是否能看到源点（一小簇白/灰起点，或与地面相连的柱根）？
  • 若一块淡影完全悬在画面中部、四周被天空包围、与地面无任何连接 → 优先判 非烟（云）。
3
判尺度档 D / M / N（按 §2 公式，不要目测"看起来小"）。若跨档，按最大边所在档记，并在备注里写实际边长。
4
判五档。按 §4 口径给出 确定烟 / 明火+烟 / 明火 / 疑似轻烟 / 非烟。拿不准一律"疑似"，并在备注写清"拿不准的点是什么"。
5
画框 + 写理由码。按 §6 画框；在备注里填至少一个理由码（下表），便于事后统计分歧来源。
理由码含义
GND能看到源点/接地
RISE连续帧可见缓慢上升
SPRD连续帧可见向外扩散
GREY灰白半透明、对比度低
CLOUD判为云（悬空/边界锐利/形态稳定）
DUST判为扬尘（贴地、横向扩散、无明显上升）
HAZE判为水汽/薄雾（大面积均匀、无源点）
GLARE判为反光/太阳眩光/灯光（高亮、过曝、无形态）
UNC拿不准（必须配文字说明）
OTHER其它明确的替代解释（建筑白顶 / 电线杆塔 / 大棚 / 塑料地膜 / 屋顶反光等，备注写明是什么）
NEAR 近场 / 起降视角：框在机场本体、无人机机身、座舱顶盖、机库内壁、水泥地特写上（画面被单一近距离物体占据，看不到地平线或天空）。
→ 这类帧属协议 §1 的「不采集」。务必用 NEAR 这个结构化码标明， 而不要只写自由文本备注 —— 入训练集时要按此码批量剔除，自由文本没法批量过滤。

级别充分条件（满足其中一条即可给出该级别）进入训练集？
确定烟
正样本		 ① 能看到源点/明确接地 且 连续帧可见上升或扩散；
② 或：有地面参照物可判尺度、烟柱形态在连续帧中连续演化且方向一致。		 是（入正样本·烟）

典型：只给了 1–2 帧；帧间跳变太大；目标贴在画面边缘被裁切。		 否（进隔离分区，默认不入训练）
非烟
负样本		 能给出明确替代解释（云/扬尘/水汽/反光/灯光/建筑白顶/田埂白膜等），且写得出理由码。
注意："我找不到替代解释"不等于"是烟"——那种情形归"疑似"。		 是（入负样本/难负）
五档怎么用：粗口径 vs 细口径
  • 粗口径（一致性门禁用这个）：把 确定烟 / 明火+烟 / 明火 三档合并为「是焚烧」， 加上「疑似」「非焚烧」共三分类 → 门禁仍是 一致率 ≥ 0.80（含义与 v1.1 的三级一致，口径可比）。
  • 细口径（参考，不设硬门槛）：五分类逐项一致率 + 混淆矩阵 → 用来定位分歧具体出在哪两档之间 （例如"明火"与"明火+烟"分不清），比一个总数字有用得多。
宁缺勿滥（项目铁律）：拿不准就标"疑似/暂缓"，绝不猜。可疑样本进隔离分区、默认不入训练集。 宁可多花人工，也不让脏数据进集。

5. 易混淆清单与区分判据

依据：本项目干扰源统计（难负分类）——云 227、电线杆 317、建筑 87、混凝土 51；其中 D 档最主要的混淆源是天空中的小块碎云。

易混物外观与本项目烟的区分判据
碎云 / 云边 白、亮、边界相对锐利、常成片 悬空（四周皆天空、不接地）；连续帧形态稳定、整体漂移；亮度更高、更"白"。
水汽 / 薄雾 大面积均匀灰白，无明显边界 覆盖范围远大于单个点源；无上升方向；随地形起伏成层。
扬尘 灰黄、贴地、横向铺开 主要横向扩散、几乎不上升；有明显的车/施工等触发源；色彩偏黄褐。
太阳眩光 / 过曝云 极亮、过曝、常在画面上部 亮度异常高、无形态；画面最上方区域（本项目已在其上生效"天空带屏蔽"，该类不再产生告警）。
夜间灯光 / 水面反光 亮斑、边缘硬、有星芒/晕 无扩散；位置固定不随帧演化形成柱状；夜间常见。
建筑白顶 / 田埂白膜 / 大棚 规则矩形、边界笔直、亮度稳定 几何规整、静止不动、有明显棱角；无半透明过渡。
电线杆 / 塔架（线索） 细长竖直白/亮线 静止、笔直、端点锐利；常与真烟同框 —— 不要把杆体画进烟框。

5.2 不采集帧怎么识别（起降 / 近场视角）

为什么单列一节：协议 §1 早就写了「机库盖子视角」不采集，但从没给出可操作的判定标准。 实测发现现有字段认不出来这类帧 —— straw_detections.scene 会把它误标成 day、 note 字段大多是空的（全库仅 7 条带"近场"备注）。所以只能靠人看图判断，标准必须写死。
特征说明
看不到地平线 / 天空画面里没有远景、没有天际线，视野被一个近距离物体占满。这是最可靠的判据。
物体尺寸突然"巨大"同一个物体（如机场盖板、机库壁）在相邻帧的正常巡航空域里很小，在起降帧里占满画面。
出现明显的机场/机体结构停机坪标识（如"H"）、舱盖、机械臂、机身蒙皮、金属反光面、混凝土特写纹理。
时间上处于起降窗口一次飞行的首尾几分钟。本项目引擎里对应 osd_skip=在仓(机库盖子) 与 landing_suppress 窗口。
处置（三步，别漏）
  1. 判定档填 非烟（近场机场盖板既不烧也没烟，别因为它"发热/发亮"就填火档）；
  2. 尺度档填 不适用（尺度档是为空中远距目标标定的，近场尺寸不可比）；
  3. 理由码勾 NEAR，备注写清"近场/机场本体"。
为什么一定要用 NEAR 而不是只写备注：入集流程要对这类帧做批量剔除 （否则它们会作为"负样本"混进训练集，教模型"机场盖板不是烟"—— 既无价值又浪费容量）。 自由文本备注的写法千差万别，没法批量过滤；结构化理由码才能。

另外：这类帧仍然值得标，不要因为「不采集」就跳过 —— 标注结果本身就是 「生产误报的取证记录」（引擎在起降阶段把框打在机场本体上，这本身是个应修的问题）。

6. 框怎么画 / 落库字段

6.1 画框规则

  • 包住整个可见烟体（含源点），不要只框最浓的一段。
  • 不要把纯天空的虚影、云的边缘、杆体拉进框内。
  • 目标被画面边缘裁切时：框到边界为止，并在备注写 EDGE。
  • 火 ≠ 烟：火焰画青框，烟柱才画红框；同一点源可同时存在，分开画两个框。
  • 一个框里火烟兼有时（锚点校准时只给一个模型框）：判定选 明火+烟， 并在备注写清"框内哪部分判火、哪部分判烟"（供后续拆框）。
  • D 档（<40px）目标很小：宁可框稍大一点点把源点含进去，也不要为了"紧"而漏掉接地证据。

7. 一致性门禁与自检

放行门禁（本协议生效的前提）
  1. 安排 2 名标注员，互不通气，各自独立标注同一批 50 张（覆盖 D/M/N × 昼/夜）。
  2. 用 §8 的一致性校验工具比对，须同时满足：
    • 【硬门槛】粗口径一致率 ≥ 0.80 —— 「焚烧 / 疑似 / 非焚烧」三分类型逐张比对
      v1.2 起「确定烟 / 明火+烟 / 明火」先合并为「焚烧」再比对：门禁只问"烧没烧"；硬按五档卡会把"都认定在烧、只是火烟成分看法不同"误判成口径失守
    • 判为"焚烧"的样本上，框级平均 IoU ≥ 0.50
    • 【硬门槛】档位（D/M/N）一致率 ≥ 0.80
    • 【参考项】五档细口径一致率（不设门槛）—— 用来定位分歧具体落在 「确定烟 / 明火+烟 / 明火」哪两档之间，比一个总数字有用
  3. 未达标 → 不开标注，先针对"粗口径分歧最大的 10 张"开会把口径写进本协议 （升版，如 v1.2 → v1.3），再重测。
  4. 达标 → 本协议生效；此后每 500 张抽样 20 张复测，防口径漂移。
关于门禁口径的一处说明（对早期简写的修正）：早期排期里写的"同档 IoU 一致性 ≥0.5"过于简略。 严格来说：档位与判定档是分类量，用"一致率"；框位置才用 IoU。v1.2 起按"粗口径 + 档位"两个硬门槛 + "五档细口径"一个参考项执行。

8. 配套工具

工具作用
build_anchor_candidates.py 按「尺度档 × 昼夜」自动从本项目真实帧里挑锚点候选，输出候选清单 + 缩略图。
只取本项目自有来源（v5_train_v5 / v6_train / straw_detections 真实机场流），刻意排除外部公开数据集。
anchor_workbench.html（本协议配套工作台） 单文件 HTML，内嵌锚点候选图。两名标注员各自独立选「三级 + 档位 + 理由码」，导出 JSON；内置一致性校验面板。
check_agreement.py 输入两份标注 JSON，输出：三级一致率、档位一致率、框级平均 IoU、分歧清单，并给出 PASS/FAIL 判定。

锚点样本怎么用：锚点不是"标准答案"，而是边界教学样本——每格 10–20 张团队公认的边界情形， 用来对齐"什么程度算确定烟、什么程度只能算疑似"。标注新品前先过一遍锚点集。

9. 附录：本项目已知陷阱（血泪教训）

#陷阱后果与对策
1正负增量不同批配平：只往正样本里堆轻烟 曾实测 +7 正塞 26 难负 → 召回 95%→75%。对策：正负必须同批、同尺度配平后再入集。
2把 source='alert' 的记录当成"真样本"直接统计 实测其中 74% 是 scene='sim' 模拟器帧。对策：统计前必须先过滤 SIM。
3把 picall 当无人机帧用 picall 实为驾驶舱/遥控器 UI 录屏截图（含地图、虚拟摇杆），坐标体系与视频帧完全不同。任何坐标统计都必须剔除。
4用"画面高度百分比"硬切天空带而不看相机姿态 证据帧有 8 种分辨率，且含俯视/舱内帧（那类画面"上方"是机库盖子）。对策：俯视帧自动禁用，并逐步改为按云台 pitch 算动态天际线。
5用降采样的缩略图坐标写回 box 缩略图与原帧分辨率不同，坐标会整体错位。对策：box 一律写原帧像素坐标（工作台负责换算）。
6只看单帧就下结论 轻烟与碎云在单帧上几乎不可分。本协议 §3 步骤 1 是硬要求。
