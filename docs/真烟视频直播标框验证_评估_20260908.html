真烟视频直播标框验证 · 需求评估
—— 用白天真烟视频做端到端"直播+标框"可控验证
编制时间：2026-09-08评估方式：代码级排查（只读）性质：可行性 + 方案

一、结论摘要

需求完全可行，且是端到端验证"直播+标框"链路的最佳方式——比真飞更可控（可反复测试、不依赖飞行窗口、不怕模型对远烟漏检）。

核心思路：把真烟视频用 ffmpeg 推流成一路"无人机流"（sikong_SIM_SMOKE），straw-engine 检测它出 bbox，simulate 触发弹窗，前端在原流画面上叠加实时检测框。

关键提醒：必须选一段"有明显烟雾"的视频——v5 stage2 对 DJI 远烟是盲的，选错视频（远烟/看不清）会测不出框，误判为链路故障。

二、需求理解

用户想用一段"白天真烟视频"，通过模拟测试机制验证：直播弹窗 + 实时标框（BboxOverlay）是否正常工作。这本质是把 DroneSimPanel 的"事件模拟"升级为"事件 + 真实视频流模拟"。

三、现状盘点（代码级）

对象现状
模拟测试（DroneSimPanel）只模拟起飞事件（触发弹窗），不提供真实视频流——局限：伪 SN 无 ZLM mirror，真实画面需真机
真烟视频资源服务器有大量白天无人机录像 /video/.../dock_media/.../DJI_..._V.mp4（可见光 V 档）
straw-engine 检测streams 写 config.json 重启加载；straw-sync.js 的 addStreamToEngine 可追加 config + 重启（现有"动态加流"方式）
bbox 接口后端 /api/drone-events/bbox?deviceSn= 查 straw-engine snapshot 的 sikong_<deviceSn> boxes（已就绪）
前端标框BboxOverlay 在弹窗原流上 canvas 叠加 bbox（已就绪）

四、实施方案

真烟视频（DJI_..._V.mp4） → ffmpeg 推流 → ZLM jsc/sikong_SIM_SMOKE → straw-sync 加流检测（config.json 追加 sikong_SIM_SMOKE + 重启 straw-engine） → simulate 触发弹窗（deviceSn=SIM_SMOKE, dockSn=白名单dock） → 弹窗播 sikong_SIM_SMOKE 流 + BboxOverlay 叠加 bbox → 验证：画面播放 + 检测框实时叠加

4.1 关键步骤

序步骤说明
1选视频：挑一段"白天 + 有明显烟雾"的 V 档视频关键！远烟/看不清的视频测不出框（模型能力问题，非链路问题）
2推流：ffmpeg 循环推流到 jsc/sikong_SIM_SMOKEstream 名带 SIM_ 前缀，与真实无人机隔离
3加流检测：straw-sync addStreamToEngine 把 sikong_SIM_SMOKE 追加 config + 重启straw-engine 拉流检测出 bbox
4触发弹窗：DroneSimPanel 或手动 simulate(deviceSn=SIM_SMOKE)触发弹窗（白名单 dockSn 用真实机场）
5验证标框：弹窗播流 + BboxOverlay 叠加看检测框是否随烟雾移动
6清理：停推流 + off-all + 从 config 移除测试流防残留

五、风险与提醒

风险说明 + 对策
模型对远烟漏检v5 stage2 对 DJI 远烟是盲的（已多次验证）。必须选"烟雾清晰、占比大"的近景视频，否则测不出框。可先离线抽帧用 stage2 预演确认能检出再上线推流
bbox 坐标偏移检测帧分辨率 vs 视频分辨率可能不一致（视频 4K/1080P，检测输入 1280）。BboxOverlay 按视频分辨率缩放，若偏移需现场调缩放
推流稳定性ffmpeg 循环推流需 -stream_loop，长测建议后台 nohup + 限时清理
防污染测试流用 SIM_ 前缀，不污染真实 drone 数据；off-all 清理模拟事件；config 移除测试流

六、与真飞验证的对比

维度真烟视频模拟真实飞行
可控性高（可反复）低（依赖飞行窗口）
成本零（已有视频）需飞行 + 燃料
烟雾可控可选清晰烟依赖现场/模型对远烟盲
验证标框充分充分
验证真实链路接近（SIM_ 替代真 SN）完全真实

结论：真烟视频模拟是标框链路的首选验证方式（可控、零成本、可反复），真飞是最终的"真实性验收"。建议先用真烟视频把标框链路调稳，再真飞验收。

七、工作量与建议

项说明工作量
选视频 + 离线预演挑 1~2 段清晰烟视频，离线抽帧用 stage2 确认能检出0.3 天
推流 + 加流检测脚本ffmpeg 推流 + straw-sync 加流 + simulate 触发，写成一键脚本0.3 天
标框验证 + 坐标校准浏览器打开驾驶舱，验证标框，偏移则调 BboxOverlay 缩放0.3 天

合计约 0.5~1 天。纯测试链路搭建，无核心代码改动。

八、结论

① 需求完全可行，是标框链路的最佳可控验证方式；
② 关键在选视频：必须选"白天 + 烟雾清晰、占比大"的近景 V 档视频（远烟测不出框）；
③ 方案清晰：真烟视频 → ffmpeg 推流 → straw-engine 检测 → simulate 弹窗 → BboxOverlay 标框；
④ 建议先离线预演：抽帧确认 stage2 能检出再上线推流，避免误判为链路故障；
⑤ 工作量约 0.5~1 天，纯测试链路搭建。

本报告基于 2026-09-08 代码级排查（DroneSimPanel / straw-engine / bbox 接口 / 视频资源）。核心结论：可行，关键在选对视频（烟雾清晰、近景）。
