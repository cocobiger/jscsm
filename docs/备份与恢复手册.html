二、两种恢复方式

方式 A：脚本化恢复（推荐，最快）

使用既有的 jsc-rollback 工具，7 步原子回滚（自动先建急救快照），无需手动搬文件。

# 查看可用快照 jsc-rollback list # 回滚到 T1 jsc-rollback restore 20260709-025452

⚠️ 该方式不含 iotcloud.env（见第三节关键提醒）。

方式 B：tarball 完整恢复（覆盖缺口）

适合需要恢复 IoTCloud 凭据、ZLMediaKit、nginx 主配置等 T1 未覆盖内容的场景，或从异地副本恢复。

# 服务器上解包（相对路径，恢复到 /） tar -xzf jsc-full.tar.gz -C / # 关键：修复 iotcloud.env 权限 chown jsc:jsc /opt/jsc/backend/iotcloud.env chmod 600 /opt/jsc/backend/iotcloud.env # 重载并启动 systemctl daemon-reload systemctl restart jsc-backend nginx -t && nginx -s reload docker start zlmediakit # 若容器仅停止

三、关键提醒（踩坑点）

① iotcloud.env 必须存在且权限正确，否则 IoTCloud 登录失败。
该文件（chmod 600，属主 jsc）存放 IoTCloud 凭据 IOT_CLOUD_*，由 systemd 经 EnvironmentFile= 注入。 旧的 Jun-17 快照不含此文件——若只回滚到那些旧快照，IoTCloud 拉取会静默失败（日志报“未设置环境变量 IOT_CLOUD_PASSWORD”）。 用 T2 tarball 恢复可确保它被正确还原。

② 数据库为 WAL 模式

备份包含 jsc.db + jsc.db-wal + jsc.db-shm。恢复时三个文件一起放回，SQLite 首次打开会自动合并 WAL，无需手动 checkpoint。

③ ZLMediaKit 是 docker 容器

配置 /opt/zlm/config.ini 已备份（bind 挂载）。容器仅停止用 docker start zlmediakit；若镜像丢失，需 docker pull zlmediakit/zlmediakit:master 并依据 zlmediakit-docker-inspect.json 重建（端口/挂载/镜像同原值）。

④ 恢复后只需确认服务状态与接口，无需改任何业务代码——JSC 拉取逻辑无日期过滤，IoTCloud 一旦恢复新记录会自动流入。

四、从异地副本恢复（服务器整盘损坏时）

  1. 在可用的目标机（同规格 Linux）重装基础环境：Node 22（nvm 路径 /home/jsc/.nvm/versions/node/v22.22.3/bin/node）、nginx、docker、systemd。
  2. 将本地 .workbuddy/backups/pre-major-20260709-025453/jsc-full.tar.gz 传到目标机（先 sha256sum -c 比对一致）。
  3. tar -xzf jsc-full.tar.gz -C / 还原全部目录与配置。
  4. 修复权限：chown -R jsc:jsc /opt/jsc/backend /opt/jsc/frontend，并单独修 iotcloud.env（600/jsc）。
  5. systemctl daemon-reload && systemctl restart jsc-backend；nginx -t && nginx -s reload；docker start zlmediakit。
  6. 放通防火墙端口：81（nginx 对外）、7170（后端内部）、6080（ZLMediaKit）；公网 81→内网 80 映射由云厂商控制台设置。

五、重大改动前 / 后的最佳实践

  1. 改动前：已建立本备份（T1+T2+异地）。再额外跑一次 jsc-rollback create 作为“改动前基准”，记下时间戳。
  2. 改动中：若改动只动前端/后端代码，可随时 jsc-rollback restore <改动前基准> 一键回退。
  3. 改动成功后：再跑一次 jsc-rollback create 固化“新稳定态”，旧的预改动快照可保留 1~2 份作兜底，其余清理。
  4. 若改动失败且无法回退：用 T2 完整 tarball 或异地副本做全量还原（见第三、四节）。
清理旧快照前务必确认新版本稳定。可用 jsc-rollback list 查看全部快照及占用空间（当前备份盘 1.4T 可用，空间充足）。
