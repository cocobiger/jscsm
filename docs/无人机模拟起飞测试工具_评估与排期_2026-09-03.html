① 背景与目标

18:00 真机未见弹窗 → 根因已修（方案 A，commit e4d4196 已上线）： 缺陷①回灌去 zlm_online===1 硬过滤 缺陷②SSE 数据帧心跳 + 45s 看门狗。 现在缺的是 T4 回归验证：需要无人机真实起飞才能确认「弹窗弹出 + 提示音 + 刷新回灌 + 断线重连」。 但真机验证受场地/时段/机场任务排班约束，不可随叫随到。

需求本质：做一个前端模拟按钮，在浏览器里"模拟一组真机起飞"，走 与真机完全相同的事件链路，把 T4 的绝大部分验收项从「等真机」变成「随时点」。

③ 关键设计决策

D1 模拟数据必须与真实数据可区分、可一键清理（最高优先级）

若模拟的 LIVE_ON 残留为「每机最新事件」，下次任何人刷新页面都会被回灌成假弹窗——污染真实运营。
强制约束： ① 模拟事件 event_id 统一加 SIM_ 前缀、raw_json 写 {"sim":true} 双标记； ② 剧本引擎强制 ON/OFF 成对，每台模拟机必以 LIVE_OFF 收尾（回灌按每机最新，OFF 结尾即不触发回灌）； ③ 面板提供 「一键全部停止」（补发所有残留 SIM_ON 的 OFF + 清理 SIM_ 历史行），异常中断也能秒级恢复现场。

D2 白名单 & 真机冲突

模拟 dock 只能选白名单 4 机场（8UUXN8N00A0LS7 三峡科技 / 8UUXN7G00A0FDP 环保局 / 8UUXN8P00A0LZ4 职教中心 / 8UUXN5500A07D1 经开区），否则白名单外不广播、模拟无效。 deviceSn 用 SIM_D_<序号> 伪 SN（不会撞真机；同机重复 ON 会被 dup 拦截，剧本天然幂等）。 若某机场真机恰好在飞，弹窗已占位 → 模拟同 dock 不同 SN 会触发满窗折叠调度，属正常行为，建议模拟前先看一眼弹窗区。

D3 权限

simulate/清理端点一律 adminOnly（绝不进 PUBLIC_PATHS）；前端按钮仅 roleAtLeast(user.role,'admin') 可见（复用 IotArchivePage 同款判断）。模拟会真触发弹窗+提示音，普通用户勿触。

D4 UI 位置与形态

DronePopupHost 占右下角（absolute right:14,bottom:12）→ 模拟面板放左下角（left:14,bottom:12, zIndex 低于弹窗），默认收起为一个灰标 🧪 模拟测试（仅 admin 可见），展开为面板：场景剧本按钮组 + 单条注入器 + 当前模拟机列表 + 一键清理。测试中在面板顶部显示 ● SIMULATING 红点提醒。

D5 局限（诚实标注）

伪 SN 在 ZLM 无 mirror → zlm_online 恒 0 → 弹窗 resolving 后在 DRONE_RESOLVE_WAIT_MS=60s 兜底自动收起。「回灌弹出 + resolving→timeout 收起」全程可测；真正的画面播放无法模拟，播放链路（ZLM mirror → HLS 出画）仍需真机或真机在飞时对照。

⑨ 结论与建议

  • 方案 B 以 ~1 天成本 换取「T4 回归随时可跑、缺陷①②修复有活体证据、未来弹窗改动有回归工具」，性价比高，建议按批 1→2→3 顺序批准开工。

  • 遗留真机项（画面播放、mirror 接入时序真体验证）诚实保留，等下次实际起飞任务顺带完成。
