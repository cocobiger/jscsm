驾驶舱 KPI 下钻扩展到其余 4 项 · 需求评估与排期

评估结论：4 项都做得到，且都是前端为主（约 1.3d）——但过程中查出 3 个必须一并处理的问题：口径混装、离线不可见、URL 泄密

一、需求理解

参照「无人机」的做法（可点击 → 弹窗列出构成明细 + 口径脚注 + 降级说明），把统计条另外 4 项也做成可下钻：监测站 / 水质点位 / 摄像头 / 重点企业。

用户价值：统计条只给"是多少"，运维/值班需要知道"是哪些"——尤其"哪几路摄像头掉线""10 家企业分别属于什么行业"。

二、四项下钻的可行性与产出（均基于线上实测）

① 监测站 · 2 座　可行且可增值

数据源字段（实测）可下钻内容
/api/stations id, name, stationName, lon, lat, enabled 站名 / 全名 / 坐标 / 启用状态，并联动实时空气质量

增值点：/api/map-points 里的 type='air' 已带 AQI / PM2.5 / PM10 / SO₂ / NO₂（实测：周家坝 AQI 78、百安坝 AQI 55）→ 下钻可显示"哪个站现在什么水平"。
⚠️ 联动方式脆弱：两表名称不一致（stationName="周家坝" vs name="周家坝监测站"），需按前缀匹配；匹配不上必须显示「—」而不是静默留空。

② 水质点位 · 5 个　可行但口径需先澄清

构成（实测）数量已有数据下钻展示
type='watermon' 流域监测站4仅名称 + 坐标名称 / 坐标 · 参数列显示「暂无数据」
type='water' 水质监测点1+ ph / do_ / nh3 / tp名称 / 坐标 / pH · 溶解氧 · 氨氮 · 总磷
🔴 口径混装问题：统计条的「5 个」= 4 个流域监测站 + 1 个水质监测点，两类不同东西相加。 下钻若平铺 5 行，用户无法解释"5"从哪来。
建议：下钻内分两组（流域监测站 4 / 水质监测点 1），并在脚注写明合计规则。这与「无人机 4 架 / 无人机机场 4 座」必须拆两个变量是同一类问题。

③ 摄像头 · 27 路　最有运维价值，但有 3 个约束

约束实测情况处理方式
口径随 tab 变化 全域 27 / 气环境 24 / 水环境 3（visibleStreams 按 category 过滤） 下钻列表必须跟随当前 tab，否则"数字 24、列表 27"对不上
离线状态原本看不见 27 路中 7 路离线（全部 autoOffline=true）：
水体监控 3（九龙园 1/2/3 号排污口）· 重点企业 4（博联热电 / 西南水泥 / 长安跨越 / 三峡国际健康城）		 下钻默认离线置顶 + 支持只看离线；统计条可加「(7 路离线)」提示
URL 含明文凭据 🔒 22 / 27 路的 url 形如 rtsp://用户:密码@host:554/… 必须脱敏为 rtsp://***:***@host:554/…；脱敏逻辑抽成单一函数，禁止直接渲染原始 url

另：thumbnail 是 base64 大图（27 张），首版不建议内联渲染，可延迟加载或只显示状态 + 最后检测时间。

④ 重点企业 · 10 家　可行，但字段很少

数据源字段（实测）缺口
/api/enterprises id, name, industry_type；location / contact 全为 null 无法显示地址 / 联系人；无经纬度 → 不支持地图定位

已可做：10 家清单（名称 + 行业）+ 行业分布聚合（现有 hover 已实现）。
可联动：map-points 中恰好有 10 个 camera:<企业名> 且名称完全一致 → 可 join 出「该企业是否有视频监控」列（当前有 4 家摄像头离线，可直接暴露）。
数据补齐：地址/联系人为空 → 需业务方补企业台账（属外部依赖，不阻塞前端）。

三、跨 4 项的共性问题（本次建议一并处理）

#问题现状证据影响
1「0 与未知」语义不统一 只有「无人机」做了「链路不可达显示 —」；其余 4 项初值均为 0（监测站 0 / 水质点位 0 / 摄像头 0 / 重点企业 0），接口 401/失败时静默保持 0 与刚修好的无人机同类缺陷：0 被读成"真的没有"。下钻弹窗若也是空表，同样误导
2/api/stations 被重复轮询 CenterPanel（10s，取数量）与 MapView（10s，取列表）各轮询一次 与司空那次同样是重复请求；且下钻需要 stations 列表 → 应提到 Context 单例
3重点企业原始列表被丢弃 CenterPanel 的 effect 内 fetch 后只保留 {total, industries}，10 条明细未进 state 下钻无数据可用 → 需保留原列表（或提到 Context）
4弹窗代码将出现 5 份重复 已有 SikongDeviceModal（约 190 行：头部/降级条/表格/脚注/关闭） 若各写一份 → 5 份重复；后续加第 6 个 KPI 再复制一次

四、方案对比

方案做法工作量优点风险 / 代价
A. 4 个独立弹窗 复制 SikongDeviceModal 模式，各写一个组件 1.2d 改动局部、易回滚；每项可自由定制 约 800 行重复代码；样式/降级/脚注逻辑各一份 → 改一处要改 5 处
B. 通用下钻弹窗（配置驱动）
推荐		 抽 KpiDrilldownModal（标题/列定义/行/分组/降级条/脚注）+ lib/kpiDrilldown.ts 放 5 份 descriptor（含已上线的无人机） 1.3d 一处封装全局复用；新增 KPI 只加配置；口径/降级/脱敏规则天然统一；与既有 StatsCell onClick 直接对接 需一次把 5 项的列语义想清楚（一次性成本），改造成本前置
C. 后端聚合成一个 /api/kpi 后端一次返回 5 个 KPI 的明细与口径 2.5d+ 口径最彻底、前端零拼装 4 个源轮询节奏不同（streams/map-points/stations 10s、enterprises 30s、sikong 15s），强行合并会牵动既有节奏；收益与风险不成比例

推荐：B（并把「无人机」也迁到同一套弹窗，做到 5 项一致）

B 比 A 仅多 0.1d，却把「5 份重复」变成「1 套骨架 + 5 份配置」，同时让降级语义、URL 脱敏、口径脚注这三件跨项规则只实现一次。

五、落地步骤

  1. 安全先行：新增 lib/maskUrl.ts（maskStreamUrl()），把所有 rtsp://user:pass@ 脱敏为 rtsp://***:***@；下钻列表禁用原始 url 渲染
  2. 通用骨架：components/KpiDrilldownModal.tsx —— props：{title, groupTitle?, columns, rows, footnote, degraded, onLocate?}；支持分组（水质点位 4+1）、离线置顶与筛选（摄像头）、降级条
  3. descriptor：lib/kpiDrilldown.ts 集中定义 5 项的列与取数（含口径脚注文案），避免散落
  4. Context 统一：新增 stations 单例轮询（替换 CenterPanel + MapView 两处），保留 enterprises 原始列表；statsCell 逐项接 onClick
  5. 降级统一：4 项各引入 available 语义（接口失败/401 → 统计条显示「—」+ 弹窗顶部降级条），与无人机同规则
  6. 联动（可选 P2）：监测站/水质点位/摄像头的行都含经纬度 → 行尾加「地图定位」按钮，复用现有 onLocate 机制
  7. 门禁与验收：tsc --noEmit + build → 部署（先备份）→ 核验 md5 → headless 逐项点开下钻断言行数与降级态

七、风险与安全

风险等级说明与缓解
RTSP 明文密码泄露高22/27 路 url 含 用户:密码@；下钻弹窗是"给人看"的界面，一旦照搬 url 等于把摄像机口令展示在大屏。→ 强制脱敏函数 + 代码评审时禁止 s.url 直出
口径混装导致误读中水质点位 4+1 合并展示 → 必须分组 + 脚注
0 与未知混淆（4 项均存在）中统一「—」降级语义；弹窗空态文案区分"确实没有"与"取数失败"
名称前缀匹配失败（监测站↔空气点位）低匹配不上显示「—」并保留原始名，便于排查
