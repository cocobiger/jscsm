复检图「点击放大看细节」需求评估与排期

需求评估 2026-08-31 关联：秸秆复检闭环 · StrawResultsView / ServerReviewPage · 画框补标

一、需求理解

业务背景：复检人员需要判断 1km 外无人机航拍画面里的细微烟雾。模型原图分辨率 2942×1732（约 2.9MP），但当前复核界面把图压缩显示：详情弹层左右并排后每张仅约 520px 宽、放大复核弹层大图上限 70vh——细微烟柱（30~130px）在屏幕上只剩几个像素，人眼根本看不清，导致误判/漏判。

一句话需求：复核用的图，点击后能放大，支持缩放/平移看细节，且放大后标注框仍能正确显示。

二、图片触点现状盘点（已逐处读码确认）

触点位置当前显示方式痛点
① 详情弹层 左右比对图 StrawResultsView.tsx DetailModal 弹层 1080px 内并排两图，各约 520px，width:100% 压缩 细节不可见（最核心）
② 画框补标 画布 StrawResultsView.tsx BoxDrawerOverlay canvas 原生分辨率绘制 + width:100% 压缩到 ~1150px 小目标画框定位难
③ 放大复核 大图 ServerReviewPage.tsx 弹层 maxHeight:70vh 适配显示（1200px 弹层） 70vh 上限仍看不清细节
④ 画框补标 画布（旧页） ServerReviewPage.tsx BoxDrawer 同②，canvas 压缩显示 同上
关键发现：画框 canvas 的坐标映射基于 getBoundingClientRect 比率（canvas.width / rect.width），天然兼容 CSS transform 缩放——放大显示后坐标自动换算正确，实现成本很低，这是本次方案能轻量落地的技术基础。

三、放大方案对比（4 选）

方案交互优点缺点结论
A · 全屏查看器（Lightbox） 点击图 → 全屏黑底查看器：滚轮缩放 + 拖拽平移 + 显隐框 + 原图/标注切换 + 1:1/适应 查看体验最佳；不改两页现有布局；组件可复用 需新写 ~150 行组件 推荐
B · 内嵌缩放平移 图片容器内直接滚轮缩放 + 拖拽（transform 就地变换） 不跳层，查看与操作同屏 左右并排各 520px 空间太小，缩放平移体验局促 备选
C · hover 放大镜 鼠标悬停显示局部放大窗 实现简单、直观 只能看局部，不能整体平移；与画框交互冲突 不选
D · 新标签页开原图 window.open 原图 URL 零实现成本 无框、无法切换原图/标注、体验割裂 不选
推荐组合：查看场景（触点①②③④）用 方案 A 全屏查看器；同时给画框 canvas 叠加滚轮缩放 + 拖拽平移（坐标自动正确），让「放大后直接画框」成为可能。

四、落地步骤与排期（2 批，合计约 3~4 小时）

第 1 批 全屏查看器组件 + 查看场景接入 ≈ 2 小时
解决「复核时看不清细节」核心痛点
  • 新建 src/app/components/admin/ImgViewer.tsx（~150 行，无第三方依赖）：滚轮缩放（0.25x~4x，以鼠标为中心）、拖拽平移、双击 1:1↔适应、顶部工具条（放大/缩小/1:1/适应/显隐框/原图↔标注切换/关闭）、Esc 关闭、标注框按百分比叠加
  • 接入 StrawResultsView 详情弹层：左右两张图均可点击 → 全屏查看（左图无框 / 右图带框，查看器内一键切换视角）
  • 接入 ServerReviewPage 放大复核弹层：大图点击 → 全屏查看
  • 快捷键冲突处理：查看器打开时暂停父层 1/2/3/5/Esc 快捷键（仅 Esc 关闭查看器）
第 2 批 画框画布内嵌缩放平移 ≈ 1~1.5 小时
解决「小目标画框定位难」，放大后可直接精确画框
  • BoxDrawerOverlay（StrawResultsView）与 BoxDrawer（ServerReviewPage）统一改造：canvas 容器加 滚轮缩放 + 拖拽平移（CSS transform 就地变换），顶栏显示缩放比例 + 复位按钮
  • 坐标映射：现有 pos() 基于 rect 比率，零改动自动适配；缩放后画框/删除命中区域同步正确
  • 缩放时框标注文字（28px）与删除按钮（20px 命中区）保持视觉大小，不随图失真
验证 + 部署 约 0.5 小时
  • typecheck 硬门禁（历史 19 条错误不动，保证 0 新增）→ npx vite build
  • 备份 /opt/jsc/frontend_bak_<ts>_<tag> → scp dist → :80/jsc/ HTTP 200
  • headless 验证（沿用 shot_compare.cjs 严格匹配法）：详情放大 / 查看器缩放 / 原图标注切换 / 画框缩放截图 4 张
  • 回滚预案：jsc-rollback restore 或前端目录整备份还原

五、冲突与风险排查

风险点影响对策
快捷键冲突（父层 1/2/3/5/Esc）查看器内按键误触复检判定查看器打开时 stopPropagation + 父层键盘监听加「查看器开启」守卫
弹层遮罩点击关闭误触点图放大时触发 onClose查看器容器 onClick={e => e.stopPropagation()}（沿用现有模式）
滚轮事件冒泡缩放时页面/弹层跟着滚动查看器内 onWheel 阻止默认 + 冒泡；父弹层 overflow 隔离
大图缩放卡顿2942×1732 大图高频重绘CSS transform（GPU 合成）而非 canvas 重绘；滚轮节流 rAF
框文字缩放失真放大后 28px 标注字变大模糊缩放系数反算，标注文字恒定视觉大小（第 2 批）
typecheck 既有 19 条错误与本次无关（Detection.lat/lng 等）不修旧债，保证 0 新增即可

六、结论

  • 需求成立且必要：当前压缩显示是复检误判的直接原因之一，放大查看是复检质量的基本保障
  • 方案 A（全屏查看器）+ 画布内嵌缩放 落地成本低：依赖现有 pos() rect 比率映射，缩放后坐标自动正确，无需改动坐标换算逻辑
  • 排期 2 批共 3~4 小时：第 1 批解决查看痛点（2h），第 2 批增强画框标注（1~1.5h），验证部署 0.5h；纯前端改动，无后端/数据库变更，风险低
  • 开工指令确认后即按批次执行
建议：若当天时间紧，可只做第 1 批（查看放大）即可解决「看不清」核心问题；第 2 批画框缩放后续补上。
