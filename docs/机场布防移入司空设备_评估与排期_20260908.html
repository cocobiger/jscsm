需求清晰、改动小、纯前端、无后端/数据风险。核心动作：把「机场布防」从后台侧边栏的独立一级菜单，降级为「秸秆焚烧监控 → 司空设备」面板里的一个子 Tab。

三、改造方案

3.1 目标结构

后台侧边栏 ├── 秸秆焚烧监控（StrawMonitorPage） │ ├── 引擎 / 流水线 / 直播 / 视频流面板 / ...（现有 Tab） │ └── 司空设备（SikongPanel） │ ├── 机场状态（现有） │ ├── 司空事件（现有） │ ├── 媒体归档（现有） │ └── 机场布防（新增 ← DockGuardPage 嵌入） ← 本次改动 └── （删除「机场布防」一级菜单）

3.2 具体改动点（3 处）

文件改动

四、需要注意的点

点说明
权限原「机场布防」minRole=admin；移入后，需确认「秸秆焚烧监控」的 minRole（viewer）是否会导致布防暴露给 viewer。若需保留 admin 限制，需在 SikongPanel 的 guard 子 Tab 加角色判断（SikongPanel 目前不接收 user 参数，需从 StrawMonitorPage 透传）
入口路径变化从「一级菜单直达」变成「秸秆焚烧监控 → 司空设备 → 机场布防」三级，多一层点击。若布防是高频入口，需权衡是否值得降级
菜单语义「机场布防」本质是「机场人员入侵检测」，与「司空设备」（机场设备状态）语义相关，归入是合理的；但「布防」更偏"安防动作"，「司空设备」偏"设备数据"，需确认用户预期的归类逻辑

唯一需要用户确认的决策点：权限。原「机场布防」是 admin 专属，移入后若跟着「秸秆焚烧监控」（viewer 可见）走，会把布防配置暴露给所有登录用户。建议保留 admin 限制（SikongPanel 增加 user 角色判断，或让 StrawMonitorPage 传入 user）。
