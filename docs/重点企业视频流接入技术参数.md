# 重点企业视频流接入技术参数

> **版本**：v1.1　　**日期**：2026-06-23　　**密级**：内部

---

## 一、概述

本文档旨在规范重点企业向江津区大屏驾驶舱系统（以下简称"JSC 系统"）提供视频监控流的技术对接标准。企业需根据现有摄像头型号和网络条件，选择适用的接入方式，并按要求提供技术参数，由我方完成平台侧的流接入配置。

### 系统网络架构说明

JSC 系统部署于公网服务器 `111.10.220.226`，外部访问**仅开放两个端口**：

| 对外端口 | 内部服务 | 用途 |
|:---:|-----------|------|
| **81** | nginx → ZLMediaKit `:6080` | 浏览器访问驾驶舱 Web + HLS/FLV 流播放（推荐） |
| **6080** | ZLMediaKit 直连 | HLS/FLV 流直连播放（备用） |

> ⚠️ **重要**：企业摄像头不需要主动连接到我方服务器。接入方式为**我方服务器主动拉取**企业摄像头 RTSP 流，经 ZLMediaKit 转码后向浏览器分发。

---

## 二、支持的视频流接入协议

JSC 系统基于 ZLMediaKit 流媒体引擎构建，支持以下协议接入企业摄像头视频流：

| 序号 | 协议 | 适用场景 | 接入方向 | 推荐度 |
|:---:|------|----------|:---:|:---:|
| 1 | **RTSP 拉流** | 主流品牌网络摄像头（海康、大华、宇视等）均支持 | 我方**主动拉取** | ⭐⭐⭐ |
| 2 | **ONVIF** | 支持 ONVIF Profile S 的标准化设备，自动发现 | 我方主动拉取 + 设备管理 | ⭐⭐ |
| 3 | **GB/T 28181** | 国标平台级联对接 | 企业设备**主动注册**到我方 | ⭐（需额外配置） |
| 4 | **HLS 直连** | 企业已对外发布 HLS 流，直接提供 m3u8 地址 | 我方拉取 HLS | ⭐ |
| 5 | **HTTP-FLV 直连** | 企业已对外发布 HTTP-FLV 流 | 我方拉取 FLV | ⭐ |

> **推荐方式**：RTSP 拉流（企业只需提供摄像头 RTSP 地址，我方主动拉取，无需企业开放额外端口给我方）。

## 三、各协议详细技术参数

### 3.1 RTSP 拉流（推荐首选）

RTSP（Real Time Streaming Protocol）是网络摄像头最通用的标准协议。我方服务器通过 ZLMediaKit 发起 RTSP 连接，**主动拉取**企业摄像头视频流。

#### 企业需提供信息

| 参数项 | 说明 | 示例 |
|--------|------|------|
| **RTSP 地址** | 完整的拉流 URL（含认证信息或单独提供账号密码） | `rtsp://192.168.1.100:554/Streaming/Channels/101` |
| **用户名** | 摄像头 RTSP 认证用户名（如 URL 中未包含） | `admin` |
| **密码** | 摄像头 RTSP 认证密码（如 URL 中未包含） | `abc12345` |
| **主码流路径** | 一般以 `/101` 结尾（全屏播放用） | `/Streaming/Channels/101` |
| **子码流路径** | 一般以 `/102` 结尾（推荐提供，用于预览） | `/Streaming/Channels/102` |

> **海康威视常见格式**：`rtsp://[用户名]:[密码]@[IP]:554/Streaming/Channels/101`  
> **大华常见格式**：`rtsp://[用户名]:[密码]@[IP]:554/cam/realmonitor?channel=1&subtype=0`

#### 网络要求

| 项目 | 说明 |
|------|------|
| **方向** | **我方服务器主动访问企业摄像头**（我方出站，企业入站） |
| **企业侧需开放** | TCP **554**（RTSP 信令 + RTP over TCP 媒体） |
| **RTP over UDP 模式** | 如需支持，企业还需开放 UDP **30000-30500**（RTP 媒体端口） |
| **推荐传输模式** | **TCP 传输**（RTP over RTSP TCP），仅需开放 TCP 554，兼容性最好 |
| **NAT/防火墙后** | 如摄像头在内网，需在企业出口网关做 **端口映射**，将摄像头 RTSP 端口映射到公网 |

#### 连接流程图

```
我方服务器 (111.10.220.226)
    │  主动发起 RTSP 连接（TCP 554）
    ├─── 企业公网 IP:554 ───▶ 企业出口防火墙（端口映射）
    │                                  │
    │                                  ▼
    │                            企业内网摄像头
    │                         （回复 RTP 媒体流）
    ▼
ZLMediaKit 拉流成功
    │
    ├─── HLS 分发 → 浏览器通过 :81 观看
    └─── HTTP-FLV 分发 → 浏览器通过 :81 观看
```

### 3.2 ONVIF 设备发现

ONVIF 是网络视频产品的国际标准化接口协议，支持设备自动发现和能力获取。

#### 企业需提供信息

| 参数项 | 说明 | 示例 |
|--------|------|------|
| **ONVIF 服务地址** | 通常与摄像头 IP 相同 | `http://[企业公网IP]:80/onvif/device_service` |
| **用户名** | ONVIF 认证用户名 | `admin` |
| **密码** | ONVIF 认证密码 | `abc12345` |

#### 网络要求

| 项目 | 说明 |
|------|------|
| **ONVIF 端口** | TCP **80** 或 **8080**（摄像头 Web 管理端口） |
| **WS-Discovery** | UDP **3702**（设备发现，可选） |
| **方向** | 我方主动访问企业摄像头（同 RTSP，均需企业侧端口映射） |

> ⚠️ 当前服务端（JSC 系统）**未开放 ONVIF WS-Discovery 接收端口**，设备发现功能受限。建议直接提供 RTSP 地址，跳过 ONVIF 自动发现步骤。

### 3.3 GB/T 28181 国标对接

适用于企业已建有视频监控平台，需要以国标方式向 JSC 平台注册并推送视频流。

#### ⚠️ 当前系统限制

| 项目 | 状态 | 说明 |
|------|:---:|------|
| GB28181 SIP 信令端口（UDP 5060） | ❌ 未开放 | Docker 容器未映射，云防火墙未放通 |
| GB28181 RTP 媒体端口（UDP 30000-30500） | ❌ 未开放 | 同上 |
| **建议** | — | 如需 GB28181 对接，需先联系我方开放相关端口 |

#### 如端口开放后，企业需提供信息

| 参数项 | 说明 | 示例 |
|--------|------|------|
| **设备国标编码** | 20 位数字 | `34020000001320000001` |
| **设备 IP / 端口** | 企业侧设备公网地址 | `112.53.x.x:5060` |
| **平台国标编码** | 我方分配（待确认） | 由我方提供 |
| **传输协议** | UDP 或 TCP | `UDP`（推荐） |
| **通道列表** | 每个视频通道的国标编码 | 逐一列出 |

### 3.4 HLS 直连（企业已发布 HLS 流）

适用于企业已通过 NVR 或流媒体服务器对外发布 HLS 视频流。

#### 企业需提供信息

| 参数项 | 说明 | 示例 |
|--------|------|------|
| **HLS 播放地址** | 完整的 m3u8 文件 URL（公网可访问） | `http://[企业公网IP]:8080/live/stream1/hls.m3u8` |

#### 要求

- 地址必须公网可达（我方服务器 `111.10.220.226` 能 `curl` 访问）
- 需支持 HTTP 跨域访问（CORS），返回 `Access-Control-Allow-Origin: *`
- 推荐 HLS 分片时长 ≤ 2 秒，保证低延迟

---

### 3.5 HTTP-FLV 直连

适用于企业已对外发布 HTTP-FLV 视频流。

#### 企业需提供信息

| 参数项 | 说明 | 示例 |
|--------|------|------|
| **FLV 播放地址** | 完整的 .flv 文件 URL（公网可访问） | `http://[企业公网IP]:8080/live/stream1.flv` |

#### 要求

- 地址必须公网可达
- 需支持 HTTP 跨域访问（CORS）
- 建议开启 `gop_cache` 以优化首屏秒开

## 四、视频编码参数要求

为保证多协议兼容（HLS / HTTP-FLV / 浏览器播放）和最优观看体验，建议摄像头按以下参数配置：

### 4.1 主码流（全屏播放用）

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| **视频编码** | **H.264**（AVC） | 浏览器原生支持，**强烈推荐** |
| 备选编码 | H.265（HEVC） | 需要服务端 FFmpeg 实时转码，增加 3-10 秒延迟 |
| **分辨率** | **1920×1080**（1080p） | 最佳画质；最低不低于 1280×720 |
| **帧率** | **25 fps** | 实时画面标准帧率 |
| **码率** | **2-4 Mbps**（CBR） | 1080p@25fps 推荐区间 |
| **关键帧间隔（GOP）** | **2 秒**（50 帧） | GOP 过大影响首屏秒开速度 |
| **码流类型** | 复合流（含音频） | 如需音频，选用 AAC 编码 |

### 4.2 子码流（预览用，推荐提供）

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| **视频编码** | **H.264** | 必须为 H.264（子码流不做转码） |
| **分辨率** | **704×576**（D1）或 640×360 | 用于列表预览和自动截图 |
| **帧率** | **15-25 fps** | — |
| **码率** | **512-1024 Kbps** | 降低带宽占用 |

### 4.3 编码不兼容处理机制

| 源编码 | 处理方式 | 影响 |
|--------|----------|------|
| H.264 | 直通播放 | 延迟最低，体验最优 |
| H.265 / HEVC | 服务端 FFmpeg 实时转码为 H.264 | 增加约 3-10 秒延迟 + CPU 负载 |
| SVAC | 不支持 | 需企业侧先转码为 H.264 |

> **强烈建议**：摄像头直接输出 H.264 编码的视频流，避免转码带来的延迟和质量损失。

## 五、网络与安全要求

### 5.1 网络可达性

JSC 系统服务器 IP：`111.10.220.226`

| 场景 | 方向 | 要求 |
|------|------|------|
| **RTSP 拉流（推荐）** | 我方服务器 → 企业摄像头 | 企业摄像头 RTSP 端口（554）须对我方服务器 IP **开放**（企业侧防火墙入站规则） |
| **企业摄像头在 NAT 后** | — | 需在企业出口网关配置**端口映射**，将摄像头 RTSP 端口映射到公网 |
| **GB28181 推送（可选）** | 企业设备 → 我方服务器 | 需我方先开放 UDP 5060 + UDP 30000-30500（当前未开放） |

### 5.2 防火墙端口开放清单（企业侧）

根据所选接入协议，企业需按以下要求配置防火墙：

#### RTSP 拉流模式（推荐，绝大多数企业适用）

| 协议 | 端口 | 协议类型 | 方向（企业侧） | 用途 |
|------|------|----------|:---:|------|
| RTSP | TCP **554** | TCP | **入站**（允许我方访问） | RTSP 信令 + RTP over TCP 媒体传输 |
| RTP（可选） | UDP **30000-30500** | UDP | **入站**（允许我方访问） | RTP over UDP 媒体传输（如启用 UDP 模式） |

> ✅ **最简配置**：RTSP over TCP 模式，企业侧只需开放 **TCP 554** 一个端口。

#### ONVIF 模式（可选）

| 协议 | 端口 | 协议类型 | 方向（企业侧） | 用途 |
|------|------|----------|:---:|------|
| ONVIF HTTP | TCP **80** 或 **8080** | TCP | 入站 | 设备管理与 RTSP 地址获取 |
| WS-Discovery | UDP **3702** | UDP | 入站 | 设备发现（可选） |

#### GB28181 国标模式（需我方先开放端口）

| 协议 | 端口 | 协议类型 | 方向 | 用途 |
|------|------|----------|------|------|
| SIP 信令 | UDP **5060** | UDP | 企业→我方（出站） | GB28181 SIP 注册与信令 |
| RTP 媒体 | UDP **30000-30500** | UDP | 企业→我方（出站） | 视频媒体流传输 |

> ⚠️ GB28181 模式需要我方服务器端同时开放对应端口，目前**暂不支持**，如需使用请提前联系我方技术人员。

### 5.3 带宽要求

| 场景 | 单路带宽（上行） | 说明 |
|------|:---:|------|
| 1080p 主码流 | **2-4 Mbps** | H.264 编码 |
| 子码流预览 | **0.5-1 Mbps** | D1 或 360p |
| 主+子码流同时拉取 | **2.5-5 Mbps** | 主码流播放 + 子码流截图 |

> 企业上行带宽需求计算公式：**摄像头数量 × 单路码率 × 1.5（冗余系数）**

### 5.4 安全要求

- 摄像头须设置**强密码**（至少 8 位，含大小写字母+数字），禁用出厂默认密码
- 建议为对接用途创建**专用只读账号**（仅具有"实时预览"权限，无云台控制/回放权限）
- 摄像头固件须更新至最新稳定版本，避免已知漏洞被利用
- 如条件允许，推荐通过 **VPN 或专线**方式实现企业内网与我方服务器的互联，避免摄像头直接暴露公网

## 八、常见问题

### Q1：摄像头不支持 H.264 怎么办？

请优先在摄像头 Web 管理界面调整编码参数为 H.264。如硬件确实只支持 H.265，我方支持服务端 FFmpeg 实时转码，但会增加约 3-10 秒播放延迟，且对服务器 CPU 有额外消耗。

### Q2：企业摄像头在内网，我方无法直接访问怎么办？

可选方案：
- **端口映射**（推荐）：在企业出口网关上将摄像头 RTSP 端口（554）映射到公网 IP，我方通过公网 IP:映射端口 访问
- **VPN / 专线**：建立安全隧道实现网络互通后，我方通过内网 IP 访问
- **企业自建流媒体中转**：企业内网 NVR 转 HLS 后提供 m3u8 地址给我方拉取

### Q3：主码流带宽占用过高？

建议企业同时提供子码流（D1 分辨率，512-1024 Kbps），用于列表预览和截图。我方系统常态只拉子码流，全屏播放时才拉取主码流，大幅降低常态带宽。

### Q4：RTSP 地址中的用户名密码必须提供吗？

如 RTSP URL 中已包含认证信息（如 `rtsp://user:pass@ip:554/...`），可不单独提供。否则需单独提供用户名和密码，我方系统会在 RTSP 握手时使用提供的凭据进行认证。

### Q5：一个 NVR 下有 16 路摄像头，需要提供 16 个地址吗？

是的。每路摄像头的 RTSP 通道地址不同（如海康 `/101` vs `/201`），需逐一列出。如支持 ONVIF，我方可通过设备发现自动获取全部通道（需企业开放 ONVIF 端口）。

### Q6：企业网络已经有视频云平台，能不能直接对接平台而不是单个摄像头？

可以。如企业平台支持 **GB/T 28181 国标级联** 或对外发布 **RTSP/HLS 汇聚流**，可直接对接平台侧，无需逐个接入摄像头。
