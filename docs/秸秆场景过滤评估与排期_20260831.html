①需求背景：4 项新发现

#发现含义本质
1机场视频 + 起飞 1 分钟机场(Dock)自带摄像头画面无意义；无人机刚起飞时镜头拍到机库盖子 → 纯干扰无效输入
290%+ 判例在农田真实秸秆焚烧围绕农田发生；白天最大干扰 = 电线杆 / 水泥地 / 天空云彩 / 远处民居训练数据
3城市场景 / 夜景不入判例城市画面干扰项过多（建筑/路灯/霓虹/车灯），夜景尤甚 → 反而不该进训练判例判例过滤
4夜间作业从严除非有明显野外火光 / 热成像特征，夜间帧一律不纳入判例推理策略
核心诉求：让无效帧不进算法判定、让无效场景不进训练判例——一条"场景红线"贯穿 推理 → 入库 → 复核 → 训练 全链路。

③4 项发现逐条评估

发现 1：机场视频 + 起飞 1 分钟 → 不判定 高可行 · 治标立竿见影

方案做法优 / 劣
A（推荐）
引擎侧停推		/api/devices 生成 dock/drone 映射 → config.json streams 加 kind 字段 → main.py 启动时 dock 流停推理不停流（驾驶舱实时画面保留）；起飞判定用 OSD 飞行状态/高度，起飞后 60s 内跳帧省算力 + 灭误报 / 需改引擎
B
后端过滤		/api/straw-alert 入库前按 streamId 类型丢弃改动最小 / 算力白烧
C
仅数据剔除		判例不进，但推理误报仍产生零代码 / 治标不彻底

发现 2：农田上下文 + 白天干扰物 中高可行 · 训练侧治本

子项做法依赖
2a 干扰物负样本从 straw_detections 误报(FP) 提取 + VLM 预筛，构建 电线杆 / 水泥地 / 云彩 / 民居 4 类难例负样本集（白天为主）VLM 预筛 + 人工复核（既有流程）
2b 农田正样本配比v5 拼装规则：正样本以农田场景为主（≥90%），呼应"90% 判例在农田"v5 训练集拼装（待确认 A/B 方案）
2c 地理围栏（可选）农田区域多边形 → 落点判断；无现成农田分布数据（area_boundary 是行政边界非农田），暂缓数据源调研

发现 3：城市场景 / 夜景 → 不入判例 高可行 · 判例可控

子项做法
3a 场景标签straw_detections 新增 scene 列：夜间=亮度<25 或时间窗；城区=lat/lng 命中街道边界 ring（area_boundary 含太白街道等城区街道）；机场期=dock 流
3b 复检页联动复检页新增"场景"筛选下拉 + 场景徽标列 + 批量"不纳入判例"标记（review_status 扩展或独立标记）
3c 导出过滤一键导出重训（第 4 批数据资产）默认排除 scene ∈ {机场期, 城区夜景, 无火光夜间}

发现 4：夜间作业从严（除非火光 / 热成像）中高可行 · 推理策略

子项做法依赖
4a 夜间阈值帧灰度均值 <25 判夜 → confFire 0.45→0.60、confSmoke 0.30→0.45（无火光不告警），阈值走 config 可调引擎侧小改
4b 热成像通道（独立项）M30T 双光（可见光 + 红外）→ 确认热成像流是否可接入 ZLM → 夜间热斑检测作第二路确认双光流接入评估
4c 判例从严夜间帧除非人工标注"火光 / 热成像确认"，否则默认进负样本v5 拼装规则

④任务排期（3 批，总量 ≈ 9~13h）

批次内容预估产出 / 验收依赖
P1 引擎侧「无效输入」过滤
① dock 流停推理（devices 映射 + config kind + main.py 跳过）
② 起飞 60s 跳帧（OSD 飞行状态 dump → telemetry 暴露飞行状态 → 每帧查询，缓存 5s）
③ 夜间阈值策略（亮度判夜 + conf 提升）		 3~4h 引擎日志确认 dock 流不再推理 / 起飞期跳帧 / 夜间告警减少；复检页误报率下降 ①无 ②OSD dump 0.5h ③无
P2 场景标签 + 复检页联动
① straw_detections 加 scene 列 + 回填（夜间/城区/机场期）
② /api/straw/results 支持 scene 筛选
③ 复检页场景下拉 + 徽标 + 批量"不纳入判例"
④ 导出重训默认排除无效场景		 2~3h API 断言 scene 筛选生效；headless 截图场景徽标与筛选；导出集统计排除比例 P1 完成（流类型）
P3 训练数据治理（治本，可并行）
① 4 类白天干扰物负样本集（电线杆/水泥地/云彩/民居，VLM 预筛 + 人工复核）
② v5 拼装：农田正样本 ≥90% + 夜场帧默认负样本
③ 热成像通道接入评估（M30T 双光 → ZLM → 热斑检测）		 4~6h
（数据工作）		 负样本集数量与分布统计；拼装集场景配比报告；热成像可行性结论 ①VLM ②v5 拼装方案（A/B 待定）③独立
建议顺序：P1 → P2 → P3。P3 为数据工作，可与 P1/P2 并行推进（不阻塞）；若时间紧，P1 单独先上即可肉眼看到误报下降。

⑤冲突排查

潜在冲突对策
OSD 飞行状态字段名未知（司空透传格式）P1-② 前置 0.5h：dump telemetry.recent() 一条实测确认字段（flight_status / mode_code / height），字段名不符则按实测适配
dock 流停推理后驾驶舱实时画面消失？只停推理不停流——ZLM 流照常，前端实时画面不受影响（main.py 跳过该 streamId 即可）
模拟流 559 条（jgfs_sim 等）混入判例P2-④ 导出时 source ∈ {sim, test} 一律排除；P2-① 标记 scene=sim 便于筛选
夜间判定口径（时间窗 vs 亮度 vs 太阳高度角）以亮度 <25 为主 + 时间窗（19:00-05:00）兜底，双条件取或；口径集中在一个函数，便于调
热成像流未接入 ZLMP3-③ 独立评估，不阻塞 P1/P2；若不可接入，夜间告警靠 4a 阈值策略兜底
机场流"起飞 60s"窗口误伤巡逻飞行窗口时长 config 可调（默认 60s）；另以"高度 <15m"辅助判断（起飞爬升期）
scene 回填与已有 review_status 冲突scene 是独立增量列，不影响已复核结果；批量"不纳入判例"用独立标记字段

⑥风险与回滚

风险等级回滚方案
P1 过滤规则误杀有效流（如某机场流实际有监拍价值）中config.json streams 每流有 enabled / kind / skipWindow 开关，回滚 = 还原 config（已有 .bak 链）+ systemctl restart straw-engine
P1-③ 夜间阈值提高后漏报（真火光被压）中阈值走 config 可调；夜间同时保留"热成像确认"路径（P3-③ 落地后双路并行）
P2 scene 回填大批量 UPDATE低先备份 straw_detections 表（CREATE TABLE bak AS SELECT）；回填按 id 分批，可精确回滚
P3 负样本误判（真烟标成干扰物）低沿用既有"VLM 预筛 + 人工复核"双保险；训练集改动走 git + /video 数据盘
引擎改造影响正在进行的推理低main.py 改动前 cp 备份（沿用 .bak 习惯）；改后先重启验证再放开

⑦结论与决策点

4 项发现全部有数据实证支撑，且现有基础设施（dock/drone 配对、OSD 遥测、亮度判夜、街道边界）足以支撑落地，无阻塞性缺口。唯一前置侦察项是 OSD 飞行状态字段名（0.5h）。
