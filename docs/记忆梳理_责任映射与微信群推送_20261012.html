5 · 风险与缺口（按优先级）

优先级缺口为什么严重
P0责任映射 0 行 模型一到位就会出告警 ⇒ 全部静默丢弃。而且这是沉默失败：前端在"推送记录"页之外看不出异常。 历史已经演过一次同源事故 —— 09-03 基线 575 条里失败 527 条，绝大多数就是"责任单位未配置"
P0推送目标群未确认 记忆记载生产曾指向不存在的群「环保测试」（推不出去）；用户指定应为「军哥」junjungege2020。重建后必须重新确认群名
P1企业微信 webhook key 需客户提供 demo 环境是模拟 key；真实 key 由客户提供后才能实战推送（是外部依赖）
P1覆盖完整性没人校验 原生产曾只覆盖 16/51 镇街 ⇒ 36 个区域（70%）静默不推送，很久才被发现。恢复时必须按 52 个乡镇街道全量核验
P1前端没有批量导入 后端 /import 支持 {rows:[…]} 数组，但前端只提交1 条 ⇒ 恢复 52 行要手工点 52 次（易漏、易错）
P1闸门口径默认 off 先推后检 ⇒ 误报会先推给街道办，靠 strawCorrection 追发更正（企微群机器人无法撤回消息）。是否改 pre 需产品决策
P2缺少推送成功率主动告警 "成功 1 / 失败 527"能长期无人发现，说明靠人看页面不可靠；应加成功率阈值告警
P2前端不校验 webhook 合法性 形如 https://qyapi.weixin.qq.com/… 与桥的 :18888/send?group= 都可；填错要等真告警才发现
