一、结论摘要

问题可修复，方案清晰：用官方 release 重装 ollama（含完整 llama-server）到 8T 数据盘（/video），不影响系统运行。

① 根因：ollama server（0.32.15）与 client（0.33.2）版本不匹配 + 运行中的进程用的是已删除的旧二进制（deleted）+ llama-server 在 /usr/local/lib/ollama/ 下确实缺失；
② 修复：下载官方 release（含 llama-server）解压到 /video，停掉损坏的旧进程，用新二进制重启；
③ 不影响系统：ollama 是独立服务（straw-engine/dji-openapi/jsc-backend 不受影响），模型复用（/video/ollama/models 已有 qwen2.5vl:7b），GPU 显存可控（VLM 随用启停，straw-engine 检测优先）；
④ 排期约 1 天。

二、问题根因（代码级排查实测）

排查项实测问题

根因总结：ollama 安装不完整/损坏——server 与 client 版本不匹配（0.32 vs 0.33），运行进程用的是已删除的旧二进制，且 llama-server（推理引擎）根本没装。/api/tags 能列模型（因为模型文件在），但推理时找不到 llama-server 二进制 → 500 错误。

三、修复方案（官方 release 重装到 8T 盘）

3.1 方案对比

方案做法优劣推荐
A. 官方 release 重装下载 ollama 官方 linux-amd64 release（含 ollama + lib/ollama/llama-server + cuda 库），解压到 /video，替换旧安装干净完整 不编译，官方原版含 llama-server；可控安装位置（/video）推荐
B. 官方安装脚本curl ollama 官方 install.sh，装到 /video（OLLAMA_MODELS 指向 /video）简单，但脚本默认装系统目录，需手动调整到 /video备选
C. 编译 llama-server按错误提示 `cmake -S llama/server --preset cpu && cmake --build --preset cpu`需源码 + 编译环境 + cuda 编译，复杂且易错不推荐

3.2 推荐方案（A）详细步骤

1. 停旧 ollama 进程（已损坏，推理 500，停用不影响其他系统） 2. 备份旧安装（/usr/local/bin/ollama + /usr/local/lib/ollama，可回滚） 3. 下载 ollama 官方 release（linux-amd64，含 llama-server）到 /video/ollama_install/ 4. 解压：ollama 二进制 → /video/ollama_install/bin/ollama lib/ollama/（含 llama-server + cuda_v12）→ /video/ollama_install/lib/ollama/ 5. 配置 OLLAMA_MODELS=/video/ollama/models（复用已有 qwen2.5vl:7b，不重下） 6. systemd 服务指向 /video/ollama_install/bin/ollama serve 7. 验证：/api/tags 列模型 + Qwen2.5-VL 推理成功 + GPU 显存占用可控

四、对系统运行的影响（可控）

影响面风险等级说明 + 对策
停旧 ollama 进程无影响旧进程已损坏（推理 500），且当前没在用 VLM（straw-engine 检测不依赖 ollama）；停用不影响 straw-engine/dji-openapi/jsc-backend
