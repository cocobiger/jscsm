一、结论摘要

预设航线功能对现有系统的影响可控，且有"零装包风险"的最安全方案。

① 对气体快检、铁路巡护系统：无影响——它们是独立系统（独立前端 location、独立后端，不共用 jsc-backend 的 node_modules）；
② 对大疆司空私有化平台：低影响——只读 MySQL 小表（37 行）+ 下载小 KMZ 文件（~2.5KB×37，一次性），负载可忽略，不写入/不改表/不锁表；
③ 对驾驶舱系统：中等影响但可控——主要是"装 mysql2 包"和"重启 jsc-backend"两个风险点，用"不装包（spawn docker exec mysql）+ 在无飞时重启"可彻底规避。

最安全方案：不装 mysql2 包（改用 spawn docker exec mysql 命令行查询），其余全部是"只读 + 缓存 + 可控重启"，对 4 个系统均无实质风险。

三、改动点与影响分析

改动点 ①：装 mysql2 包（jsc-backend node_modules）

影响系统风险等级影响说明
驾驶舱（jsc-backend）中npm install 可能污染 node_modules（引入新依赖/版本冲突/装失败），影响 jsc-backend 启动；之前 ioredis 装失败过一次
气体快检 / 铁路巡护无独立 node_modules，不共用
司空2 平台无docker 容器栈，不受影响

缓解（最安全方案）：不装 mysql2 包，改用 spawn 'docker exec mysql mysql -uroot -p... -e "SELECT ..."' 命令行查询。零装包风险——jsc-backend 的 node_modules 完全不动，彻底消除此风险。

改动点 ②：连司空2 MySQL 读 system_route（只读）

影响系统风险等级影响说明
司空2 平台（MySQL）低只读 SELECT 小表（37 行），负载可忽略；不写入/不改表结构/不锁表；连接用后关闭
驾驶舱 / 气体快检 / 铁路巡护无只读司空2 MySQL，不影响这些系统

改动点 ③：下载 KMZ 航线文件（司空2 5443）

影响系统风险等级影响说明
司空2 平台（web 5443）低小文件（~2.5KB）× 37 条，一次性下载，负载可忽略
其他系统无—

改动点 ④：加后端接口 + 重启 jsc-backend

影响系统风险等级影响说明
驾驶舱（jsc-backend）中（可控）重启短暂中断（~3s）：SSE 断开但前端已有 45s 看门狗自动重连；正在进行的请求失败
驾驶舱（straw-engine/dji-openapi）无独立 systemd 服务，不重启
气体快检 / 铁路巡护 / 司空2无独立系统/容器，不受影响

缓解：在无无人机飞行时重启 jsc-backend（红线约束），避免中断在飞无人机的检测/弹窗。重启前查 OSD 确认无在飞。

改动点 ⑤：前端 build + 部署

影响系统风险等级影响说明
驾驶舱（jsc 前端/nginx）低build 本地进行；部署覆盖 /opt/jsc/frontend（静态文件，index.html no-cache，nginx 无需重启）
气体快检 / 铁路巡护无不同 location（/qitijsc/、/tielu/），不动它们的目录
司空2 平台无—

改动点 ⑥：spawn docker exec mysql / unzip（子进程）

影响系统风险等级影响说明
司空2 平台（MySQL 容器）低spawn docker exec mysql 查询，只读，一次性，负载低
系统（unzip）低spawn unzip 解压 KMZ，CPU 占用低，一次性
其他系统无—

五、缓解措施（最安全方案）

#措施消除的风险
1不装 mysql2 包，改用 spawn docker exec mysql 命令行查询彻底消除"装包污染 jsc-backend node_modules"风险（改动点①）
2只读 + 缓存：MySQL 只读小表（不写入/不改表/不锁表）；航线启动加载一次 + 定时刷新（不频繁查/下载）对司空2 平台负载可忽略（改动点②③⑥）
3可控重启：jsc-backend 在无无人机飞行时重启（红线约束）；前端 SSE 已有 45s 看门狗自动重连消除"重启中断在飞检测"风险（改动点④）
4部署前备份：jsc-backend 代码 + /opt/jsc/frontend 前端，可回滚任何部署问题可快速回滚
5部署后验证 4 个系统：驾驶舱（接口+前端）/ 气体快检 / 铁路巡护 / 司空2 平台，确认都正常确保改动未波及其他系统

七、结论

① 系统隔离良好：气体快检/铁路巡护/司空2 平台与驾驶舱各自独立，改动不波及；
② 对气体快检、铁路巡护：无影响（独立系统）；
③ 对司空2 平台：低影响（只读小表 + 下载小文件，负载可忽略，不写入/不改表/不锁表）；
④ 对驾驶舱：中等影响但可控——用"不装包（spawn docker exec mysql）+ 在无飞时重启 + 备份 + 验证"可彻底规避风险；
⑤ 最安全方案已明确：不装 mysql2 包，其余全部"只读 + 缓存 + 可控重启"，对 4 个系统均无实质风险，可放心开工。

本报告基于 2026-09-08 服务器系统隔离边界盘点（3 个独立 systemd 服务 + 独立 docker 容器栈 + nginx 独立 location + jsc-backend node_modules 43M/11 包）。核心结论：预设航线功能对现有系统影响可控，最安全方案为"不装包 + 只读缓存 + 可控重启"，可放心开工。
