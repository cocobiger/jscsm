二、需要与平台方对齐的 8 个问题

#问题证据请求平台方
18 类环保算法只部署了 1 类 IoTCloud 21 通道算法配置全为 unsoilcover；/scene/model/list 只有 1 个"视频轮播"模型 确认堆场扬尘/道路扬尘/违规排污/固废×2/侵占岸线 是否计划部署；如不部署，我方将从 UI 撤下这些空壳算法
2算法类型命名的三层不一致 底层 spill → API 输出 unsoilcover → 业务标签「冒装」→ 标注类别「真违规·装载物未覆盖」 确认 spill 与 unsoilcover 的准确对应关系；建议统一命名口径，避免下游误解
3「未覆盖」检测存在结构性误报 实测样本：① 空载平板货车（货斗无货）被判"未覆盖" ② 已盖灰色篷布的重载车（渝DP173挂）仍被判"未覆盖" 请修复检测逻辑：需能区分「空车 / 已盖篷布 / 真未覆盖」三种状态
4误报导致单日数千条刷屏 09-06~09-10 连续 5 天 3,373~5,220 条/天（合计 20,567 条），因路口每辆货车经过都触发 配合 #3 修复；修复前我方已实施通道级过滤（见第三节）
53 个通道 channelName 为空 56331706881318000205 / …204 / …305 在 IoTCloud 与 iot_channels 中均无名称，仅 NVR(172.16.8.51) 补录这 3 路摄像头的点位名称（含实际安装位置）
6dust 类型来源不明 存量 125 条 aiType='dust'（07-21~08-31），当前 IoTCloud 无此算法配置 确认 dust 是已下线的算法还是别名（我方已按"历史遗留"标记为已处置，不再展示）
7通道算法配置与产出不一致 通道"桐子园码头"配「堆头未覆盖」却产出 dust/AI分析/type；配「道路扬尘」的 7 个通道从未产出道路扬尘 确认 通道算法配置是否真的生效于云平台侧（我方已改为"按记录所属通道配置做白名单过滤"，配置即生效）
8车牌识别能力未接入我方 analyseInfo 含 plate（渝A025991）+ plate_conf（0.855）；EasyAIoT 另有 plate-service（7001 端口，catcher+crnn） 确认车牌数据是否可开放给我方（当前我方未消费该字段）

四、建议的对齐方式

  1. 先确认「能力清单」：请平台方书面给出——IoTCloud 与 EasyAIoT 当前实际部署的算法清单（名称 / 状态 / 适用场景 / 对应通道），与本文第二节 8 个问题逐条答复。
  2. 再定「部署计划」：我方期望的 8 类环保算法中未部署的 6 类，是否有部署计划？若无，我方将从驾驶舱 UI 撤下（避免"点了没数据"的体验问题）。
  3. 最后修「检出质量」：优先修复「未覆盖」误报（问题 #3/#4），这是刷屏的根因；修复后我方撤销通道屏蔽，恢复完整告警。
  4. 可选：车牌识别数据开放（问题 #8）—— 若开放，我方可在告警卡片展示车牌，提升处置效率。
