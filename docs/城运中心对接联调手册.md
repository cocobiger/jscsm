# 城运中心对接联调手册

系统：环保局驾驶舱系统（JSC）。本文档供城运中心（全景影像视频平台 / 三级城运中心）研发对接驾驶舱使用，描述两条链路的接口与联调步骤。所有响应体统一为 {"code":int,"message":str,"data":{...}}。

## 一、对接链路总览

- 链路 A（入站 · 城运 → 驾驶舱）：全景影像视频平台按《全景影像视频平台接口规范 V1.0》调用我方订阅接口，推送摄像头识别事件与短视频。这是驾驶舱 AI 视频告警（堆头未覆盖、扬尘等）的标准事件来源。

- 链路 B（出站闭环 · 驾驶舱 → 城运 → 驾驶舱）：预警经城运中心 API 推送至政务系统处置，处置完成后城运中心回调我方接口回传处置结论，形成 pushed → processing → closed 闭环。

## 二、网络与鉴权

- 接口部署于电子政务网隔离区；入站与回调接口采用「来源 IP 白名单 + 可选令牌」鉴权（复用同一守卫 chengyunGuard）。

- IP 白名单：由驾驶舱侧在 CHENGYUN_ALLOW_IPS 配置城运平台出口 IP；不在白名单返回 403。

- 令牌（可选）：若驾驶舱配置了 CHENGYUN_CALLBACK_TOKEN，请求须带请求头 X-Callback-Token 且与之相等，否则 401。当前阶段令牌不强制（预留）。

- /client/* 不经过 /api 会话鉴权；/api/smart-push/callback 已加入公开路径绕过会话鉴权。

## 三、接口速查表

| 方向 | 方法 | 路径 | 用途 | 鉴权 |
| --- | --- | --- | --- | --- |
| 入站 | POST | /client/handle_event | 推送摄像头识别事件 | IP 白名单(+令牌) |
| 入站 | POST | /client/handle_event_other | 推送关联短视频 | IP 白名单(+令牌) |
| 出站(城运接收) | POST | <城运侧提供的接收地址 api_url> | 驾驶舱推送预警事件 | 由城运侧定义 |
| 回调 | POST | /api/smart-push/callback | 城运回传处置结论 | IP 白名单(+令牌) |
| (内部) | POST | /api/smart-push/history/:id/close | 人工一键结案 | 会话 Bearer |

## 四、链路 A：入站接口（城运 → 驾驶舱）

### 4.1 POST /client/handle_event

请求体为 JSON，字段如下（与《全景影像视频平台接口规范 V1.0》一致）：

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| eventId | 是 | string | 事件ID（规则 sjzl-摄像头id-毫秒时间戳）；作为 warning.id 幂等键，重复推送不重复落库 |
| eventTime | 是 | string | 事件时间（上海本地时，如 2024-09-15 07:14:25；无时区标记，落库补 +08:00） |
| cameraId | 是 | string | 摄像头ID → 关联 iot_channels 通道与通道名 |
| eventType | 是 | int | 枚举 1~17 → aiType（映射见下文） |
| subType | 否 | string | 子类型 |
| confirm | 否 | int | 1 已审核 / 0 未审核 → 决定告警级别（未审核=1，已审核=2） |
| eventImgSmall | 否 | string | 小图网络地址 → picUrl（经 /api/iot-image 代理预览） |
| eventImgBig | 否 | string | 大图网络地址（优先于 small） |
| longitude | 否 | number | 经度；落库口径：经度 = longitude |
| latitude | 否 | number | 纬度；落库口径：纬度 = latitude（已与城运确认） |
| districtName | 否 | string | 区县 → location |
| townName | 否 | string | 乡镇/街道 → location |
| address | 否 | string | 详细地址 → location |
| elevation | 否 | number | 云台上下角度 |
| azimuth | 否 | number | 云台水平角度 |
| absoluteZoom | 否 | number | 放大倍数 |
| processEventId | 否 | string | 流程事件标识 |
| processEventStatus | 否 | int | 流程事件状态：0 未识别 / 1 识别到（可用于流程结束判断） |
| watermarkImage | 否 | string | 水印图地址 |
| count | 否 | int | 识别物数量 |
| total | 否 | int | 总数 |
| presetPosNum | 否 | string | 预置点编号 |
| presetPosName | 否 | string | 预置点名称 |
| distance | 否 | number | 预估距离 |

请求示例：

```
curl -X POST http://[驾驶舱对外地址]/client/handle_event \
  -H "Content-Type: application/json" \
  -H "X-Callback-Token: <若启用>" \
  -d '{
    "eventId": "sjzl-119-202409150714251",
    "eventTime": "2024-09-15 07:14:25",
    "cameraId": "119",
    "eventType": 4,
    "confirm": 1,
    "eventImgSmall": "http://10.120.49.14:30100/img/s.jpg",
    "eventImgBig": "http://10.120.49.14:30100/img/b.jpg",
    "longitude": 108.3893,
    "latitude": 30.8050,
    "districtName": "万州区",
    "townName": "某街道",
    "address": "某路某号"
  }'
```

响应示例（成功）：

```
{"code":200,"message":"请求已成功","data":{}}
```

- eventId 幂等：以 eventId 为 warning.id 做 upsert，重复推送不重复落库、保留首见时间。

- 经纬度口径（已确认）：经度 = longitude 字段，纬度 = latitude 字段。

- eventType 枚举映射（节选，完整见接口说明文档）：4 → 堆头未覆盖；7 → 扬尘；3 → 烟尘；5 → 生物质燃烧。

### 4.2 POST /client/handle_event_other（短视频）

请求体：eventIds（事件ID，可逗号分隔）、fileUrl（录像文件地址）、cameraId。

```
curl -X POST http://[驾驶舱对外地址]/client/handle_event_other \
  -H "Content-Type: application/json" \
  -d '{"eventIds":"sjzl-119-202409150714251","fileUrl":"http://10.120.49.14:30100/vid/xxx.mp4","cameraId":"119"}'
```

响应示例：

```
{"code":200,"message":"请求已成功","data":{"updated":1}}
```

## 五、链路 B：出站闭环

### 5.1 驾驶舱 → 城运 推送（城运侧接收）

- 城运侧需提供接收地址（api_url），驾驶舱按预案模板 POST 推送预警事件。

- 推送报文（城运侧会收到的字段）：event_type / location / lat / lon / level / value / standard / description / time / trigger_count / event_ids，以及关联键 push_id（=本次推送记录 ID）、callback_url（可选，驾驶舱对外回调地址）。

- 回执关联：驾驶舱推送的 HTTP 响应头带 X-Push-Id: <push_id>；同时报文体模板变量含 push_id。城运侧请保存该 push_id，回调时原样回传。

城运侧收到的推送报文示例（取决于预案模板，字段名可配）：

```
POST <城运接收地址>  Content-Type: application/json
{
  "event_type": "堆头未覆盖",
  "location": "九龙沙场",
  "lon": 108.38, "lat": 30.80, "level": 2,
  "trigger_count": 23, "event_ids": "id1,id2",
  "push_id": "9f3a...uuid",
  "callback_url": "http://[驾驶舱对外地址]/api/smart-push/callback"
}
```

### 5.2 城运 → 驾驶舱 回调 POST /api/smart-push/callback

- 关联键（三选一，优先级从高到低）：请求头 X-Push-Id > 报文体 push_id > 报文体 event_id；三者皆缺返回 400。

请求体字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| disposal_status | 是 | 处置状态：processing（受理中）/ closed（已结案）；其他取值默认按 processing 处理 |
| disposal_result | 否 | 处置结论 / 结果文本 |
| disposal_operator | 否 | 处置人 / 责任单位 |
| disposal_time | 否 | 处置完成时间（建议上海时字符串） |
| (兼容别名) | 否 | status / result / remark / operator / disposalResult / disposalOperator / disposalTime，字段名可由 callback_field_mapping 适配 |

请求示例：

```
curl -X POST http://[驾驶舱对外地址]/api/smart-push/callback \
  -H "Content-Type: application/json" \
  -H "X-Callback-Token: <若启用>" \
  -H "X-Push-Id: 9f3a...uuid" \
  -d '{
    "disposal_status": "closed",
    "disposal_result": "已现场核查并责令整改苫盖",
    "disposal_operator": "城运中心-张三",
    "disposal_time": "2024-09-15 09:30:00"
  }'
```

响应示例（成功）：

```
{"code":200,"message":"请求已成功","data":{"status":"closed"}}
```

- 状态机：disposal_status=processing → 关联事件置 processing（可回退）；disposal_status=closed → 关联事件置 closed（不可逆），并写回处置结论、标记待结案。

- 超时：事件处于 pushed 超过 24h 无回调，驾驶舱前端标红提示人工跟办。

## 六、联调检查清单

- 驾驶舱侧已将城运出口 IP 加入 CHENGYUN_ALLOW_IPS 并重启服务。

- 用已知 eventId 推送一次，确认返回 200 且驾驶舱落库（source=chengyun-platform）。

- 重复推送同一 eventId，确认幂等不重复落库。

- 驾驶舱侧配置测试推送预案推送到城运接收地址，确认城运收到 push_id（响应头 X-Push-Id）。

- 城运用收到的 push_id 调 /api/smart-push/callback（processing），确认状态流转。

- 再调 closed，确认事件置 closed 且处置写回。

- 缺 push_id 调用，确认返回 400；非白名单 IP 调用，确认返回 403。

## 七、错误码

| HTTP | code | message | 含义 / 处理 |
| --- | --- | --- | --- |
| 200 | 200 | 请求已成功 | 成功；data 含业务字段 |
| 400 | 400 | 缺少 push_id / 缺少 eventId | 缺少必填关联键；请携带 X-Push-Id 头或报文体 push_id |
| 401 | 401 | 令牌无效 | 配置了令牌但 X-Callback-Token 不符；请核对令牌 |
| 403 | 403 | 来源 IP 不在白名单 | 调用方 IP 未在 CHENGYUN_ALLOW_IPS；联系驾驶舱侧加白 |
| 404 | 404 | 推送记录不存在 | push_id 在驾驶舱无对应推送记录；确认 push_id 正确 |
| 500 | 500 | 处理失败 | 服务端异常；查看驾驶舱日志 |

## 八、待与城运确认

- 驾驶舱对外回调地址（公网/政务网域名）— 影响城运侧调用 /api/smart-push/callback 的 URL。

- 城运侧接收地址 api_url（驾驶舱推送目标）。

- 是否启用令牌鉴权（CHENGYUN_CALLBACK_TOKEN），以及令牌交换方式。
