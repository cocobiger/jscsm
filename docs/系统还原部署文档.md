# 系统还原部署文档

> 万州区生态环境局智能AI大数据控制台 —— 备份还原指南
> 适用：在一台全新服务器上完整复现本系统（含历史数据）

---

## 一、备份包内容说明

备份包（`jsc-backup-YYYYMMDD.zip`）包含：

| 内容 | 说明 |
| --- | --- |
| 前端源码 | `src/`、`index.html`、`vite.config.ts`、`package.json` 等 |
| 后端源码 | `server/*.js`（8 个模块）、`server/package.json` |
| **运行数据** | `server/data/`（视频流、地图点位、采集数据、预警、短信联系人/模板/历史/黑名单等全部 JSON） |
| 配置 | `.env`、`.npmrc`、`pnpm-workspace.yaml`、`pnpm-lock.yaml` |
| 文档 | `docs/`、各 `.md` 说明文件 |

**不含** `node_modules`（约 304MB，靠 `pnpm install` 按锁文件精确重装，保证依赖版本一致）。

---

## 二、新服务器环境要求

| 软件 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 18（推荐 22） | 后端运行 + 前端构建。必须支持原生 fetch（Node 18+） |
| pnpm | ≥ 9（推荐 11） | 包管理器。装：`npm i -g pnpm` |
| Git | 任意版本 | **必须装**——依赖里有从 GitHub 拉取的包（mpegts.js 的 webworkify-webpack） |
| 操作系统 | Windows / Linux 均可 | 纯 JS，跨平台 |

**外部服务**（按需，非系统本体）：
- ZLMediaKit：视频流转发服务器（RTSP→FLV/WebRTC），内网部署
- MQTT Broker：如 EMQX，传感器数据接入用
- 云MAS 短信网关：需网络可达（外网或专线）

## 三、还原步骤

### 1. 解压备份包

```powershell
# 解压到目标目录，例如 D:\jsc
# Windows 可直接右键解压；或命令行：
Expand-Archive jsc-backup-YYYYMMDD.zip -DestinationPath D:\jsc
```

### 2. 安装 Git（如未安装）

下载 https://git-scm.com/download/win 一路默认安装，装完**重开终端**，验证：
```powershell
git --version
```

### 3. 安装依赖

```powershell
cd D:\jsc
npm i -g pnpm          # 如未装 pnpm

# 前端依赖
pnpm install

# 后端依赖
cd server
npm install            # 后端用 npm 即可（无 workspace 协议）
cd ..
```

> 若 `pnpm install` 报 git+ssh 拉取失败（Host key verification failed），说明走了 SSH。本项目已在 `pnpm-workspace.yaml` 用 override 强制走 https，正常不会遇到。如仍遇到，执行：
> ```powershell
> git config --global url."https://github.com/".insteadOf "git@github.com:"
> ```

### 4. 检查配置

- **`.env`**（前端高德地图 Key）：确认 `VITE_AMAP_KEY` / `VITE_AMAP_SECURITY`。如换了高德账号，改成新 Key。
- **`server/data/config.json`**（后端核心配置）：包含
  - `apiKey`：后端鉴权 Key（前端管理后台要填这个）
  - `zlmHost/zlmPort/zlmSecret`：ZLMediaKit 连接信息（**新服务器的 ZLM 地址若变了，需更新**）
  - `sms`：云MAS 短信参数（ecName/apId/secretKey/sign 等）

### 5. 启动

```powershell
# 后端（端口 7070）
cd server
npm start
# 控制台会打印 API Key，记下

# 前端（另开终端，端口 5173）
cd D:\jsc
pnpm dev
# 或生产构建：pnpm build  → 用任意静态服务器托管 dist/
```

浏览器访问 `http://localhost:5173`（或服务器内网 IP:5173）。

### 6. 数据验证

启动后确认历史数据完整：

```powershell
# 健康检查：各数据文件条数
Invoke-RestMethod -Uri "http://localhost:7070/api/health/files"

# 视频流数量
Invoke-RestMethod -Uri "http://localhost:7070/api/streams" | Measure-Object | Select Count

# 采集数据数量
(Invoke-RestMethod -Uri "http://localhost:7070/api/collected?limit=9999").Count
```

数量与备份前一致即还原成功。

## 四、外部依赖的重新对接（换服务器后必查）

数据和代码能完美复现，但以下**指向外部服务的地址**在新环境可能要改：

| 项目 | 检查点 | 在哪改 |
| --- | --- | --- |
| ZLMediaKit | 新服务器能否访问 ZLM？地址/端口是否变 | 管理后台「视频流管理」或 `POST /api/zlm/config` |
| MQTT Broker | broker 地址、新服务器能否连通 | 管理后台「MQTT 配置」 |
| 云MAS 短信 | 新服务器**公网 IP 要重新加入平台白名单**（否则 NOT_WHITE_IP） | MAS 平台接口白名单 |
| 高德地图 | 内网环境地图加载不出（需互联网）；如换 Key 改 `.env` | `.env` |
| 摄像头 RTSP/数据源 | 流地址、采集源地址在新网络是否可达 | 管理后台对应配置页 |

## 五、数据目录说明（server/data/）

| 文件 | 内容 | 自愈机制 |
| --- | --- | --- |
| streams.json | 视频流配置 | 缺失/损坏自动种子默认值 + 滚动备份 .bak1/2/3 |
| map_points.json | 地图监测点位 | 同上 |
| datasources.json | 采集数据源配置 | — |
| collected.json | 历史采集数据 | 滚动备份 |
| warnings.json | 预警记录 | — |
| collect_logs.json | 采集日志 | 滚动备份 |
| sms_contacts/templates/history/blacklist/reports.json | 短信相关数据 | — |
| config.json | API Key + ZLM + 短信配置 | **重要，务必备份** |
| logs/ | 运行日志（可选） | — |

> 所有 JSON 文件采用原子写 + 回读校验 + 滚动备份（.bak1/2/3），单文件损坏可从备份恢复：
> `POST /api/health/restore` body `{"file":"streams","ver":1}`

## 六、定期备份建议

数据持续增长（采集、预警、短信历史），建议定期备份 `server/data/` 整个目录即可（核心数据全在这）。代码不变时只需备份数据。

简单备份命令（Windows）：
```powershell
$date = Get-Date -Format "yyyyMMdd"
Compress-Archive -Path "D:\jsc\server\data" -DestinationPath "D:\backup\jsc-data-$date.zip"
```
