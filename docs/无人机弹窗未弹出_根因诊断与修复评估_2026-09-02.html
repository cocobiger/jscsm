一、问题背景

2026-09-02 18 时许，大疆司空 2 平台四台机场无人机先后起飞执行巡检任务。驾驶员在驾驶舱（外网入口，页面书签为 /jsc/v5review.html，经 SPA fallback 实际加载驾驶舱主页）全程未看到无人机回传弹窗，也未听到提示音。

预期行为：机场上报 LIVE_ON（直播开始）后，驾驶舱右下角自动弹出该无人机回传画面窗口（≤2 窗 + 3 队列），并发出提示音；窗口满时按既定调度策略折叠。

二、诊断结论（先行）

后端链路全程正常 —— 事件在服务端"发出去了"，但浏览器"一条都没收到"

12 起真实起降事件（18:10~19:24）全部白名单命中、入库、SSE 广播，mirror 拉流也成功（18:10:41 流上线 H264 960×720）。弹窗未出现的根因在前端事件投递层：① 页面挂载"回灌在飞"逻辑硬性要求 zlm_online=1，而真实事件入库时 mirror 流尚未拉起（落后约 9 秒）→ 回灌恒为空；② SSE 通道无心跳、半死连接不被感知、后端重启后浏览器未能自动重连 → 实时广播全部错过。

四、根因分析

①【P0】回灌"在飞事件"硬性过滤 zlm_online=1 —— 结构性缺陷

前端挂载时调用 GET /api/drone-events?limit=80 回灌在飞无人机，v1（DroneLivePopup.tsx L369）与 v2（DronePopupHost.tsx L147）均执行同一过滤：

rows = latest 每机最新记录
       .filter(whitelisted === '1' && status 以 'LIVE_ON' 开头 && Number(zlm_online) === 1)  ← 硬条件

而服务端在 ingest 的同一瞬间查询 ZLM 判定 zlm_online（server/drone-events.js L107：online = on ? await zlmOnline(deviceSn) : 0）。mirror 拉流代理由 dji-openapi 在事件后约 9 秒才建立（18:10:32 事件 vs 18:10:41 addStreamProxy）→ 真实事件入库时 zlm 恒为 0 → 回灌条件永不满足。

后果

只要驾驶员不是"广播瞬间恰好盯着页面且 SSE 存活"，而是起飞后打开或刷新页面，就 100% 看不到弹窗 —— 这正是本次场景。

②【P0】SSE 无心跳、半死连接不感知、重连不可靠

  • 连接"半死"（浏览器后台挂机 / 网络路径失效）时，nginx 与后端均不感知，广播 res.write 写缓冲成功即记 ok=1，不代表客户端真实收到（18:10:32 即此情形）；
  • SSE 流无周期心跳注释行，前端无法用"超时无消息"判活；
  • 18:20 后端重启切断连接后，浏览器 EventSource 的自动重连未成功（access log 无新接入）——v1 仅处理 readyState===CLOSED 场景，半死→重启 的组合未被覆盖；
  • 无 visibilitychange 恢复时强制重连的兜底，大屏切回前台后不会自愈。

③【P2】提示音依赖用户手势解锁（WebAudio 自动播放策略）

提示音经 WebAudio 播放，须有一次 pointerdown/keydown 解锁（unlockAudioOnGesture）。大屏无人操作时浏览器静默拦截 → 事件即使到达也无提示音。本次属次要因素（事件本身未达）。

怀疑点结论

生产前后端版本不同步排除：生产 23:22 版（index-zoRLADhB.js）已含 v2 弹窗代码（drone-popup-off / stream-status / sikong_ 特征齐全）；后端 stream-status 端点已存在。18:00 线上为 14:28 部署的 v1，两代代码均受根因①影响。

八、风险与回滚

主要风险

  • 并行会话部署窗口：23:12 / 23:22 均有并行部署；改码/提交前先 fetch 对齐，推送冲突以远端为准 rebase；
  • Windows 沙箱 src/ 消失：git 写操作前先 baseline commit；大编辑后避免 git 写操作窗口期；
  • 后端重启瞬时断 SSE：心跳上线后前端具备自动重连自愈，属可接受窗口（<10s）；
  • 回灌去掉 zlm 过滤后，页面会回灌"已停飞未收到 OFF"的陈旧在飞（概率低，4s 轮询会以 stream-status 实测纠正）。

回滚方案

  • 前端：还原 /video/backups/jsc_frontend_20260902_dronefix/ 中 index.html + assets 至 /opt/jsc/frontend/ 根；
  • 后端：还原 server/drone-events.js 后 systemctl restart jsc-backend；
  • git：本次改动独立 commit，git revert 或 git reset --hard 至 b088113 即可整体回退；
  • 数据侧无结构变更（无新表/新字段），DB 零风险。

九、结论与建议

  1. 本次"未见弹窗"非链路故障，而是前端"事件恢复/投递"两个结构性缺陷叠加 SSE 断连所致 —— 代码缺陷，非配置、非白名单、非 nginx 问题；
  2. 缺陷①（回灌 zlm 硬过滤）v1/v2 同源，必须在 v2 上修复，否则"起飞后开页面"场景将持续失效；
  3. 缺陷②（SSE 无心跳/不可重连）导致实时广播也可能漏 —— 大屏 7×24 挂机场景下尤为致命；
  4. 建议按方案 A 立即修复并部署（改动集中、风险可控、回滚路径清晰），并在下次真实起飞窗口完成 T4 真机回归；
  5. 排障遗留建议：用户驾驶舱书签由 /jsc/v5review.html 更正为 /jsc/。
