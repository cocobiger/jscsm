二、我错在哪（4 处，按严重度排序）

错误 ① 【最要紧】我把"不用改生产数据"的问题，当成了数据治理问题

我 9/16 的判断是：企业「重庆市九龙万博新材料科技有限公司」的摄像头名为「重庆市九龙万博监控1/2」，命名与全称不一致，故去改了两条生产流记录的名字。

但实测记录显示——这两条流的 location 字段本来就是企业全称：

4aec3f51…重庆市九龙万博监控2重庆市九龙万博新材料科技有限公司命名不一致 → 改数据

只要匹配键支持 location，这个问题本可零改动解决。我当时确实看到了 location 字段，却把它读成"说明期望标签是企业全称"（用来佐证改名），而没想到它本身就能当匹配键 —— 这是判断错误，不是信息不足。

我改动了不该改的生产数据。已备份可回退：/opt/jsc/backend/backups/streams_rename_20260916052330.json（含两条原始记录全文 + 回滚命令）。是否回退见第四节。

错误 ③ 「N 家有离线」把两种不同含义合并了

实测 10 路离线里：

autoOffline=true9 路后端巡检探测判定不可达会 下次探测通就恢复
offline=true + autoOffline=false1 路（重庆湘渝盐化有限公司）人工下线不会 见 stream-monitor.js：「手动 offline 优先：用户手动下线的流不被探测覆盖为在线」

我写的「N 家有离线」是一个数字，值班看到会默认"等一会就好"——但湘渝盐化那一路是人工下线，等多久都不会回来。这两类必须分开标注。

四、修正方案（3 个决策点）

#问题选项我的建议
D1 匹配键是否加入 location ① 匹配键 = name 或 location（归一化后精确 → 再前缀）
② 维持只按 name，漏配的靠人工改名补齐		 ①。这是最贴合本系统数据实情的做法：本系统多把企业名写在 location（万源玻璃、九龙万博都是），只按 name 必然持续漏配。
D2 九龙万博两路流名是否回退 ① 回退为「重庆市九龙万博监控1/2」（恢复原状，靠 location 匹配）
② 保留「…（通道102/201）」		 ②保留。理由 名字里带通道号对运维更可读（原「监控1/2」看不出是哪个通道），且回退需再动一次生产数据；D1 落地后两种命名都能匹配，保留成本为零。
D3 离线是否区分来源 ① 下钻「视频监控」列区分「离线(巡检)」/「已下线(人工)」，并说明后者不会自动恢复
② 维持「离线」一个词		 ①。人工下线的流不会被巡检自动恢复，值班若不知道会一直空等；数据字段已有（autoOffline），改动只在展示层。

若 D1、D3 采纳，改动范围（预估）

  • lib/kpiDrilldown.ts：specEnterprises 匹配键改为 name/location 双键；CameraLike 加 location；「视频监控」列的离线文案按 autoOffline 区分；脚注同步改写
  • 不需要后端改动（/api/streams 已返回 location 与 autoOffline）
  • 工作量约 0.3d，含真实页面回归（万源玻璃应为 2 路、湘渝盐化应标注"人工下线"）

五、我这次错在哪（复盘）

#根因以后怎么做
1 看到反例却不改假设：location = 企业全称 这个反例摆在眼前，我却用它去佐证"该改名"，而没有回头质疑"是否一定要改数据"。 出现"要不要动生产数据"这种高成本选项时，先穷举零改动方案（换匹配键、加映射表），确认都不行再动数据。
2 只审"有没有匹配上"，没审"有没有漏"：我验证的是"10/10 家都匹配了"，没做反向扫描"哪些摄像头没有任何归属"。 联动类改动必须做双向核对：正向（每家能否找到摄像头）+ 反向（每路能否找到归属），本次反向扫描才揪出「万源玻璃大门干道」。
3 把实时量当静态事实写进交付：离线状态是秒级变化的量，我写成报告结论且未标注截止时间。 实时状态类结论一律写成「截至 YYYY-MM-DD HH:mm，X 家离线」，并在界面脚注同步说明。
4 把两种语义合成一个指标：人工下线与巡检离线性质完全不同，合并成「N 家有离线」丢失了关键差异。 指标设计时先问"这个数字背后有几种不同的成因"，不同成因要在展示层可分辨。
