3. 关键决策（为什么这么做）

决策理由
安装根放 /data/HBJSC（不是 /opt） 系统盘 1T、数据盘 5T；并把 /video 做成软链 → /data/video， 实测写文件落 sdb1 ⇒ 后续大数据不会写满系统盘。
后端用「9 月代码 + 7/9 数据库」 7/9 库只有 coll_* 旧表；9 月版多 14 张表且都用 CREATE TABLE IF NOT EXISTS ⇒ 能自动补建缺表、基础表沿用 7/9。反之若用 7 月代码，会和 9 月前端大量 404。
Node 装 22（不是 apt 的 12，也不是 20） 后端 store-db.js 用 require('node:sqlite')，该内置模块 Node 22.5+ 才有； apt 只提供 12.22.9。
ZLM 源码编译 + 只配 on_publish ZLM 的 hook 返回非 200 会拒绝推流/播放；本机后端只有 /api/zlm/publish-check 这一个路由， 其余 hook 必须置空。基线改用 release 自带官方完整默认配置。

4. 施工中踩到的坑（已修，记录备查）

坑现象与修法
--strip-components=1 包无目录前缀 打包时用了 cd server && tar czf … *.js（tar 里无 server/），解包时把文件名也剥掉 → 一个文件都没落地， 且 tar 退出码 0，set -e 不拦。改为在仓库根打包，并回看 tar -tzf 结构。
Node 20 → ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite 服务不断重启（restart counter 17）。装 Node 22.23.3 并把 systemd ExecStart 指过去后正常。
CMake 产物目录 + || true 写成 release/linux/Debug/*，实际是 Release/；而 cp … || true 把失败吞了 → systemd status=203/EXEC。关键拷贝不能用 || true，拷完必须验存在。
ZLM 端口键名记错 SSL http 端口其实是 [http] sslport（不是 [https] port），RTP 区间是 port_range。 修正后监听正确、不再占 443。
7/9 备份里的 config.ini 是默认模板 里面是 80/554/1935/8080（docker 时代默认），而生产是 6080/5540/1936/4443 ⇒ 改用软件自带默认做基线。
npm 在 pnpm 结构上崩 Cannot read properties of null (reading 'matches') ⇒ 补单个包改用「临时目录 npm i 再 cp -r」。
