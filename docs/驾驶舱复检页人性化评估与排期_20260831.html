② 用户视角痛点分析（按严重度分级）

P0 单条复核操作链太长 —— 512 条 × 5 次点击 ≈ 2560 次点击

复核一条（详情驱动）：点「查看」→ 看左右比对 → 点「真烟/误报」→ 点「关闭 ✕」→ 回到列表找下一条未复核 → 再点「查看」 对比旧页（连续驱动）：按 1/2 判定 → 自动跳下一张（gotoFocus）→ 继续按
  • 缺"判定后自动下一张"：详情弹层内按 1/2/3 后停留原地，必须手动关闭 → 滚动找下一行 → 再打开。每条约多 2~3 次点击，512 条多出 1000+ 次点击（旧页 gotoFocus 已有此能力，新页未移植）
  • 行内只有「真烟/误报」两个按钮，没有「稍后」：拿不准的帧必须进详情才能标"稍后处理"（快捷键 3），打断连续复核流
  • 列表页无批量操作栏：旧页有「本页全选 / 本页全误报 / 批量真烟 / 批量误报 / 所选标为烟」，新页完全没有 —— 而截图里大量 31.9%~47.3% 低置信度帧（picall_random/low 来源），正是"批量误报"的典型场景

P0 分页只有「上一页/下一页」，无页码跳转、无待复核优先

  • 654 条 = 14 页，只能逐页点「下一页」，无法直接跳第 8 页；无页码数字按钮
  • 已复核帧只做半透明处理（opacity 0.62）但仍混在列表里，未复核帧不置顶 —— 翻页时容易重复看到已处理的行
  • 无排序：不能按置信度升序（低置信度最该先复核）、不能按时间/流排序

P1 统计卡是"死数字"，不能点击联动筛选

  • 点「待复检 512」理应直接切到 复检状态=pending 的列表 —— 现在必须手动去下拉框选
  • 点「已推送告警 / 待复核后推」同理，7 张卡全部不可点

P1 筛选维度缺"按流"与"低置信度优先"

  • 来源下拉只有 alert/picall/picall_random/low/random，没有按 stream_id 筛选 —— 想看"这台无人机报了什么"只能靠肉眼在流列里找
  • 置信度筛选只有 ≥0.5/≥0.4/≥0.3/≥0.25，没有"只看低置信度"（<0.5） —— 低置信度帧才是复核重点，应一键过滤

P2 复核进度不记忆、无撤销入口、误点无保护

  • 刷新页面回到默认筛选/第 1 页，不记得上次复核到哪（旧页 localStorage 记状态）
  • 列表行内无「撤销」按钮（撤销要进详情按 4）—— 误点「误报」后找回路径长
  • 批量误报一旦引入，无二次确认 → 存在整页误标风险，需防误触

④ 改进方案（按批次，全部纯前端，后端零改动）

批次 1 批量操作栏 + 自动下一张（≈2h，直击 512 积压）

  • 表格上方加批量操作栏：本页全选（checkbox）/ 批量真烟 / 批量误报 / 批量稍后 / 取消选择 —— 复用旧页 submitMany 逻辑（循环调 /api/review/submit，后端无需改动），加二次确认弹层防误触
  • 详情弹层判定后自动下一张：维护 focusIndex 数组（当前筛选+排序下的行序），按 1/2/3 判定后自动定位到下一条未复核帧并重新打开弹层；弹层标题显示「3 / 512」进度
  • 行内补「稍后」按钮：真烟/误报/稍后 三按钮齐平，快捷键 3 在行内直达

批次 2 分页升级 + 待复核优先（≈1h）

  • 页码按钮组：1 2 3 … 14 + 上一页/下一页 + 跳页输入框（复用 v5review 页码样式）
  • 待复核优先排序：默认按「待复检 → 时间倒序」排列，已复核沉底（与 v5review 同款"未复核置顶"交互）；筛选态下自动保持
  • 排序下拉：时间↓ / 时间↑ / 置信度↑（低先）/ 置信度↓

批次 3 统计卡可点 + 筛选增强（≈1h）

  • 7 张统计卡全部可点击：点「待复检」→ 筛选自动切 pending；点「确认真烟/误报」同理；当前激活态高亮
  • 来源下拉加「按流」：从数据里提取去重 stream_id 列表；置信度加「只看 <0.50」 快捷项
  • 筛选态 + 页码 + 排序记忆到 localStorage（刷新不丢）

批次 4 体验细节（≈0.5h）

  • 行内「撤销」直达按钮（误点快速回滚）+ 批量二次确认
  • 列表行键盘导航：↑↓ 移动光标行 + Enter 打开详情 + 1/2/3 直接判定当前行（全键盘连续复核）

⑥ 结论与建议

  • 推荐全部 4 批一次执行（≈5h）：批次 1+2 解决"复得快"（估摸能把 512 条复核时间从 ≈2.5 小时压到 ≈40 分钟），批次 3+4 补齐筛选与体验
  • 若时间紧，至少做批次 1（批量 + 自动下一张）—— 单独即可解决 80% 积压痛点
  • 批次 2 的"待复核优先排序"与批次 3 的统计卡联动是低风险高感知的小改动，可顺手并入
  • 所有改动不触碰后端 / 不触碰已有 4 批成果（比对/放大/画框/gate/报表），纯增量
