6 · 复跑可行性结论

脚本能否原地复跑说明
p0_01可以（幂等）已实跑验证：识别非空、只补缺失、软链/隔离校验全绿
p0_02修正后可，之前会把 /usr/local/bin/node 指回 v20改后装 v22，但仍会动系统 PATH
p0_03否会把在跑的 backend 挪成 .bak 并重解；需先停服务 + 快照
p0_04修正后可（但依赖 /tmp/deploy_A）修后走 pnpm-safe 回填
p0_05否（github 不通）需 gitee/离线源码
p0_06否会覆盖线上 ZLM 配置并重启 ZLM
p0_07基本可以其 sed 现已多为 no-op；会重启 ZLM + 跑门禁
e2e / fix_warnings可以（自带还原/清场）e2e 用桩模型+合成视频，测完还原；fix_warnings 幂等
复跑前置是易失的： p0_03/p0_04 依赖 /tmp/deploy_A/（7 个 payload，含 39MB backend_base.tgz）。 它在 /tmp（重启即失） ⇒ "分阶段可复跑"只在 /tmp/deploy_A 存活期内成立。换机/重启后必须重新 stage。
