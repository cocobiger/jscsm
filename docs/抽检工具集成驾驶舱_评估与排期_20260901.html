抽检工具集成驾驶舱「秸秆焚烧监控」评估与排期

日期：2026-09-01 项目：万州秸秆焚烧监控驾驶舱（v5 主线） 状态：待用户确认后开工

一、需求背景

P3-2a 阶段已产出 VLM 负样本分类抽检工具（neg_verify.html，53 帧 4 类干扰物人工复核）。当前它是独立静态页面（nginx 直出，复核结果存浏览器 localStorage，导出 CSV 手动回传）。

用户诉求：把抽检工具作为「手动启动的常驻页面」集成进驾驶舱后台「秸秆焚烧监控」模块，使 VLM 分类结果 → 人工复核 → 训练数据消费的闭环在驾驶舱内完成，从而更快迭代算法（负样本分类质量直接决定 v5 训练集的干扰物配比）。

二、现状盘点

维度现状集成后的目标
入口 独立 URL：http://111.10.220.226:81/neg_verify.html（nginx alias，无鉴权） 驾驶舱「秸秆焚烧监控」新增 tab，登录态进入
数据源 静态 JSON：/v5_candidates/neg_classified.json（359 帧 VLM 分类结果） 后端 API 提供（可增量刷新、可版本化）
复核结果 浏览器 localStorage（key: neg_verify_v1），单机、可清缓存丢失、CSV 手动导出 后端 DB 持久化，多人/多浏览器共享，训练脚本可直接拉取
主题 独立深色页面，与驾驶舱玻璃拟态（cockpitTheme）不一致 复用驾驶舱主题与组件模式
鉴权 无（任何人都可访问，局域网环境风险低但存在） 走 authFetch + 后端 token 校验
后端接口 缺失 /api/review/neg-classify-verify 仅存在于 JS 注释（预留），未实现 新增 GET 列表 + POST 提交两个接口

三、方案对比

方案 做法 优点 缺点 工时
A · iframe 嵌入 StrawMonitorPage 加 tab → <iframe src="/neg_verify.html">，零改动现有页面 最快（0.5h）；老页面零风险 样式割裂；localStorage 与登录态无关；复核结果仍需手动 CSV；无法按用户审计；双滚动条体验差 0.5h
B · React 组件 + 后端持久化 推荐 新建 NegClassifyVerify.tsx（移植抽检逻辑 + 驾驶舱主题 + authFetch）；后端新增 GET/POST 接口 + straw_neg_reviews 表；StrawMonitorPage 加 tab 登录态鉴权；复核结果入 DB（多人共享、可审计、训练脚本可拉）；主题统一；保留老页面可并行 中等工作量；需后端建表（幂等，风险低） 4~6h
C · 训练数据工作台 在 B 基础上加：批次管理、VLM 分类版本对比、一键导出训练格式（neg_classified → YOLO 负样本）、统计仪表 功能最全，算法迭代闭环最完整 工作量大；当前 v5 训练尚未派生（v5_train_v4 为空壳），过早建设易返工 12h+
推荐方案 B：成本 4~6h，覆盖核心诉求（常驻入口 + 结果入库 + 快速迭代）；C 的「批次/导出」能力等 v5 派生数据集跑通后再按需追加，避免返工。A 可作为 0.5h 临时过渡（若急需），但建议直接上 B。

四、落地步骤（批次排期）

  1. 批次 1 · 后端接口与数据表（约 2h）
    改造 /opt/jsc/backend/review.js（或独立 straw_neg_review.js 挂载），initReviewDb 幂等建表
    接口说明
    GET /api/straw/neg-classify?batch=1返回抽样列表：{fp, cats, raw, ts} × 53 帧 + 已复核状态（从 DB 合并）；batch 支持按批次拉取（当前 batch=1 固定 53 帧）

六、风险与回滚

风险项等级缓解与回滚

八、结论

可行且推荐，采用方案 B。理由：

  1. 集成成本低：驾驶舱「秸秆焚烧监控」已是 8-tab 容器（StrawMonitorPage），新增第 9 个 tab 为纯增量，不触碰既有功能；前端组件逻辑已有现成 neg_verify.js 可直接移植。
  2. 闭环价值高：复核结果从 localStorage 升级到 DB 后，gen_v5_neg_from_reviews.py 可随时拉取已复核分类生成训练负样本——「VLM 分类 → 人工复核 → 训练数据」全链路在驾驶舱内完成，算法迭代从「天级」缩短到「小时级」。
  3. 风险可控：新增表/接口全部幂等隔离，旧抽检页保留作回退路径，全程不影响生产推理（straw-engine）与 P2 场景治理成果。

决策点：① 是否按方案 B 开工（或先 A 过渡）② 图片路径若 /api/review/image 白名单未覆盖 record/ 目录，是否接受追加白名单（1 行配置）。
