0 · 为什么这是当前最长关键路径

现状：`straw-engine` 服务在线但空管线——无模型、无流、`workers=0`。 现网模型 stage9_1920（白天）/ stage3_0909（夜间）随 7TiB 盘消失且无任何副本； 训练集（v5_train_v5 / v6_train / day_0911 / hardneg…）同样归零。
P0~P2 已回位，唯一能让系统"真正干活"的只剩这一步。
关键认知：采集受飞行窗口（天气/空域/批次）约束，无法用人力换时间； 其余阻塞项（司空重装、GPU 驱动、SMTP）都可"等人给凭据"即刻解决。所以采集必须今天就排期。

3 · 拍摄参数（决定"等效目标像素尺寸"，比分辨率更重要）

项要求为什么
分辨率只允许 960×720 / 1280×720 / 1440×1080无人机原生帧；2968×1732 / 2560×1329 等桌面截图比例一律拒收（历史污染源）
等效目标尺寸同一场景尽量拍到多档：目标像素高 ≈20 / 40 / 80 / 150px补尺度缺口的核心变量；批次间尺度要配平
吊舱角度正俯 + 斜俯各占一半；记录 gimbalPitch斜俯才有"远山轻烟"；pitch 可做动态天际线屏蔽
变焦远距离场景用长焦拉近小目标样本的主要来源
飞行高度记录 AGL 与变焦倍数（随帧入库）便于事后分析"哪档尺度最难"
帧率/码流≥25fps，码流尽量高抽帧需清晰；时序判别需要连续帧

4 · 昼夜时段安排

时段重点产出
白天 09:00–16:00大镇/乡耕地；小目标（长焦/高飞）正样本（整框精确）+ 白天难负
黄昏 17:00–19:00点火集中时段；逆光/低照度过渡域样本（模型最易漏的时段）
夜间 19:30–23:00明火/火光（安全前提下）；城区 & 堆场夜景夜间正样本 + 大量夜间难负
夜间飞行需满足空域/照明/返航条件；宁可少采，不冒险。

5 · 抽帧口径（沿用现成工具，别自己造）

infra/vlm/pull_frames_v5.py —— MinIO 直播段 → ffmpeg -vf fps=1/<interval> -q:v 3 → 抽完立即删 mp4（数据盘红线：不囤视频） 
python3 pull_frames_v5.py --plan 本轮清单.csv --interval 2 --out /video/shujuji/datasets/v5_live_frames

  • 输出目录命名保持 {sn}_{day}_{base}，与现管线一致
  • 断点续跑：脚本自带 pull_frames_state.json，重复运行自动跳过

6 · 标注与入库（协议 v1.2 · 7 道闸）

环节口径
五档标签确定烟 / 明火+烟 / 明火 / 疑似轻烟 / 非烟
门禁口径只走粗口径：焚烧（确定烟+明火+烟+明火）/ 疑似 / 非焚烧，≥0.80 硬门槛；五档细口径仅参考
尺度分档≥0.80 亦为硬门槛；IoU ≥0.50 仅在正式批次
正负同批匹配新增正样本必须同时配足难负（历史教训：+7 正塞 26 难负 ⇒ 召回 95%→75%；配比失衡会直接掉点）
难负来源城区屋顶/车辆、堆场蒸汽、水面与玻璃反光、云/碎云、远山薄雾
holdout 校验集沿用 v5_train_v5/splits/val.txt（117 帧，含 7 真烟）⇒ 保证跨版本横向可比
防污染预检tmp/audit_dataset_ui.py（PIL 只读头，秒级）：分辨率 × 宽高比判据，拦截桌面截图/标注平台截图/撕裂坏帧

10 · 红线与风险

  • 不囤视频：抽帧后立即删 mp4（数据盘只有 5T，且系统盘严禁写大数据）。
  • 禁入黑名单：SIM_SMOKE、机场直连流 —— 混入即污染，会让指标虚高、上线即失效。
  • 尺度偏移要配平：不同架次的等效目标尺寸若差异过大，会让模型偏向某一档。
  • 夜间安全优先：不满足条件就不飞，宁可少采。
  • 标注宁缺勿滥：可疑样本隔离、默认不入集。
  • 产物外备：数据集/模型必须离开该主机留副本（本次事故的核心教训）。
