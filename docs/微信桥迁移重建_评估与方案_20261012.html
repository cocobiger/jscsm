4 · 重建方案（分三部分，标注自动化程度）

4.1 Windows 侧（172.16.8.16）—— 主要工作量

#步骤可否自动说明
1建 C:\wxbridge\，通过 SMB 上传 wechat_bot_server.py + requirements.txt + 一键部署脚本✅ 我现在就能做SMB 可写已实测
2装 Python 3.11（VM 无 Python）。两种方式：① VM 联网→静默安装；② 走 embeddable zip（免安装，SMB 传即可）⚠ 需在 VM 执行推荐 embeddable，避开 GUI 安装器
3pip install -r requirements.txt + 驱动库⚠ 需 VM 联网若无外网：本机 pip download 出 wheel 包再 SMB 传
4启动服务 + 防火墙放行 TCP 18888 + 开机自启（NSSM 已无 → 用计划任务或启动文件夹）⚠ 需在 VM 执行一次 -File 跑完
5微信扫码登录小号；把目标群在「最近会话」打开一次；关闭微信自动更新❌ 必须人工扫码无法自动化（README 明确）
6跑 list_groups.ps1 导出群名清单✅ 可自动用于填 webhook 的 group=
执行方式必须先定：第 2/3/4 步要在 VM 上跑命令，三条路：
  • (a) 你手动：我把一键 deploy_bridge.ps1 通过 SMB 放好，你在 VM 上双击/跑一次 —— 最稳，推荐
  • (b) RDP 自动化：我已装好 Xvfb + xfreerdp + xdotool，可自动注入 —— ⚠️ 但记忆里有真实事故：xdotool 焦点错位会把整段命令打进微信输入框并回车发出。 安全姿势只允许「super+r → 粘文件路径 → Enter 跑 -File」
  • (c) 计划任务：需先创建任务，而创建本身也要执行命令 ⇒ 仍绕回 (a) 或 (b)

5 · 风险提示

  • 封号风险：wxauto 系属非官方自动化，违反微信用户协议 ⇒ 务必用小号、控制频率（README 已强调）。
  • 升级即失效：微信一旦升到不支持的版本，桥立即废。⇒ 无论走哪条路线，都必须关掉自动更新并记录当前版本。
  • 单点依赖：Windows 机掉线 / 微信掉线 = 推送全断。历史已因"桥挂着"丢过 4 条推送（9/25）。⇒ 必须加 /health 探活。
  • OCR 路线的不确定性：路线 A 的 wechatauto-replica 依赖屏幕渲染，对分辨率/DPI 敏感；需实测发送成功率，别假设它能一次跑通。
  • 不要用 RDP 自动化注入命令：有真实事故（命令被打进微信输入框发出去）。若用自动化，只允许"粘文件路径跑 -File"。
