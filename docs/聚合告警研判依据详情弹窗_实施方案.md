# 聚合告警「研判依据」详情弹窗 — 实施方案

> 状态：5 个设计分支已全部收敛（grilling），待实施
> 日期：2026-07-10

## 一、需求

在驾驶舱「实时告警」面板，当某通道+某 AI 类型触发推送规则（聚合告警）时，卡片右侧显示「详情」按钮。点击后弹出居中弹窗，展示该聚合告警的**研判依据**：

- **顶部摘要**：规则名、通道、AI 类型、时间窗、阈值、命中条数、最高等级、最新时间
- **下方成员证据网格**：被折叠的全部原始记录（缩略图 + 时间 + 置信度），可点击放大

让运营人员直观看到"这条告警为什么被推出来"，作为研判依据。

## 二、设计分支收敛（grilling）

| 分支 | 决策 |
|------|------|
| Q1 详情入口 | **只对聚合告警**显示「详情」按钮（单条原始告警不显示） |
| Q2 详情内容 | **摘要 + 成员证据网格**（先做核心，趋势/建议后续迭代） |
| Q3 数据链路 | **轻量轮询**（聚合只带 `memberIds`）+ **点详情时按需拉取**成员（`POST /api/warnings/by-ids`） |
| Q4 UI 容器 | **居中弹窗（Modal）**，与 `AlertHistoryModal` 风格一致 |
| Q5 卡片呈现 | **最新缩略图 + 计数徽章**，带紫色「聚合」标签与单条卡片视觉区分 |

## 三、对现有系统的影响

### 数据链路变更
- `DashboardContext` 实时轮询从 `/api/warnings?limit=100` → `/api/warnings?limit=100&aggregate=1&lightweight=1`
- 后端 `queryWarningsAggregated` 增加 `lightweight` 参数：为 `true` 时聚合对象**不返回 `members` 数组**（只返回 `memberIds`），降低每 10 秒轮询的 payload
- `AlertHistoryModal`（"更多"弹窗）保持用 `?aggregate=1`（带 `members`），不受影响

### 新增接口
- `POST /api/warnings/by-ids`：接收 `{ ids: string[] }`，返回对应 warning 的成员详情数组（`id / picUrl / createdAt / level / aiConfidence / channelName / aiType`）。供详情弹窗按需拉取。

### 前端组件
- `AlertPanel.tsx`：新增聚合告警卡片渲染分支（缩略图+计数徽章+聚合标签+详情按钮）；新增详情弹窗状态管理
- 新建 `AlertEvidenceModal.tsx`：研判依据弹窗组件（摘要区 + 成员图片网格 + 加载态 + 点击放大）
- `DashboardContext.tsx`：`AlertItem` 增加 `isAggregate / ruleId / channelSipId / aiType / windowHours / count / maxLevel / latestTime / memberIds` 字段；`toAlert` 支持聚合对象转换

### 兼容性
- 聚合告警的 `id` 使用 `ruleId + channelSipId + aiType` 组合键（保证去重稳定）
- 单条原始告警不受影响（`isAggregate` 为 falsy 时走原渲染逻辑）
- `AlertHistoryModal` 的聚合 drill-down 逻辑不变

## 四、实施 Phase

### Phase 1 · 后端：轻量聚合 + by-ids 接口
**文件**：`server/store-db.js`、`server/index.js`

1. `queryWarningsAggregated({ limit, lightweight })`：
   - `lightweight=true` 时，聚合对象不push `members`，只保留 `memberIds`
   - `lightweight=false`（默认）时，行为不变（兼容 AlertHistoryModal）

2. `index.js` 的 `GET /api/warnings`：
   - `?aggregate=1&lightweight=1` → `queryWarningsAggregated({ limit, lightweight: true })`

3. 新增 `getWarningsByIds(ids)` in `store-db.js`：
   ```js
   function getWarningsByIds(ids) {
     if (!ids || !ids.length) return []
     const placeholders = ids.map(() => '?').join(',')
     return db.prepare(`SELECT data_json FROM warnings WHERE id IN (${placeholders})`).all(...ids)
       .map(r => JSON.parse(r.data_json))
       .map(w => ({ id: w.id, picUrl: w.picUrl, createdAt: w.createdAt, level: w.level, aiConfidence: w.aiConfidence, channelName: w.channelName, aiType: w.aiType }))
   }
   ```

4. 新增 `POST /api/warnings/by-ids`（登录即可）：
   ```js
   app.post('/api/warnings/by-ids', (req, res) => {
     const { ids } = req.body || {}
     if (!Array.isArray(ids) || ids.length === 0) return res.json([])
     res.json(store.getWarningsByIds(ids))
   })
   ```

### Phase 2 · 前端类型 + 数据链路
**文件**：`src/app/context/DashboardContext.tsx`

1. `AlertItem` 扩展：
   ```ts
   export interface AlertItem {
     // ... 原有字段
     isAggregate?: boolean
     ruleId?: string
     aggregateChannelSipId?: string | null
     aggregateAiType?: string
     windowHours?: number
     count?: number
     maxLevel?: number
     latestTime?: string
     memberIds?: string[]
   }
   ```

2. `toAlert(w)` 支持聚合对象：
   - `w.isAggregate === true` 时，构建聚合 AlertItem（id = `agg-${w.ruleId}-${w.channelSipId}-${w.aiType}`，type = `AI视频分析 · ${w.aiType}`，location = `w.channelName`，level = `w.maxLevel`，imageUrl = undefined 或最新成员图）
   - 否则走原逻辑

3. `sync()` 轮询改为 `authFetch('/api/warnings?limit=100&aggregate=1&lightweight=1')`

### Phase 3 · AlertPanel 聚合卡片 + 详情按钮
**文件**：`src/app/components/AlertPanel.tsx`

1. 聚合卡片渲染分支（`alert.isAggregate` 为 true 时）：
   - 左侧：最新缩略图占位（无图时显示「聚合」图标）+ 计数徽章（`{count}+`）
   - 中间：紫色「聚合」标签 + 时间 + `{通道} · {AI类型}` + `24h 内 {count}+ 条 · 最高{等级}`
   - 右侧：「详情」按钮

2. 详情按钮 `onClick`：设置 `evidenceAlert` state，触发 `AlertEvidenceModal`

3. 单条卡片保持原样，不显示「详情」按钮

## 五、风险与回滚

| 风险 | 应对 |
|------|------|
| 轮询改 `aggregate=1` 后单条告警消失 | 聚合接口对未达阈值/无规则的组仍返回单条原始对象，不影响 |
| `by-ids` 接口被滥用拉取大量数据 | 限制单次最多 100 条；需登录 |
| 聚合卡片 id 冲突 | 用 `agg-{ruleId}-{channelSipId}-{aiType}` 组合键，与单条 `iot-` 前缀不冲突 |
| 前端 bundle 体积 | `AlertEvidenceModal` 代码量小（~150 行），影响可忽略 |

**回滚**：部署前做 tarball 快照；若出问题，还原 `store-db.js` + `index.js` + 前端 bundle 即可，数据库无结构变更。
