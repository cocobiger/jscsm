驾驶舱「无人机」指标接入司空设备数 · 需求评估与排期

评估结论：数据早已在系统里（司空 4 架已打通），当前取错了源 —— 不是缺数据，是接了"人工点位"而非"司空设备台账"

一、需求理解

驾驶舱前台指标条「无人机」当前显示 0 架（截图），诉求改为：取司空设备里的无人机数量。

评估范围：这个数该从哪来、现在为什么是 0、口径怎么定、改动影响哪些地方。

二、现状排查（均带源码/实测证据）

🔴 发现 1：当前取的是「人工维护的地图点位」，与司空完全无关

// src/app/components/CenterPanel.tsx:68
const uavCount = mapPoints.filter(p => p.type === 'uav').length
  • mapPoints 是后台可人工维护的点位集合（MapPointManage.tsx 的 POINT_TYPES 含 'uav'＝无人机机场）
  • 现网该类型点位为 0 个 → 「无人机」恒显示 0
  • 而 司空链路早就打通了（MapView.tsx:98 每 15s 轮询 /api/sikong/devices 画地图机场标注）—— 数据在，只是没接到 KPI 上

🟡 发现 3：一个变量被用在两处、语义不同（必须一并处理）

使用处代码实际语义若直接改源会怎样
统计条StatsCell label="无人机" value={uavCount} unit="架"无人机（架）✅ 正确
气环境覆盖卡OverlayCard "气体快检设备" → 无人机机场 {uavCount}座机场（座）⚠️ 文案写"机场"但取值变成"无人机数"，语义错位（今日恰好都=4，掩盖问题）

⟹ 改造时需拆成两个变量：droneCount（无人机·架）与 dockCount（机场·座）。

三、口径定义（需先拍板）

口径取数方式今日值特征建议
A. 司空接入台账 /api/sikong/devices 中 drone.droneSn 非空计数 4 架 稳定、不随飞行变化，与"设备台账"语义一致；接口轻 推荐
B. 司空通道建流数 /api/sikong/live-streams 里 role==='drone' 计数 4 架 数值与 A 一致，但该接口重（含 OSD 遥测 + 签名 URL）、5s 轮询，给 KPI 用会浪费带宽 不推荐
C. 当前在飞 sikongLive 或 OSD droneInDock!==1 0 架 会随飞行 0↔4 频繁跳变，KPI 视觉抖动，值班人员易误判设备失联 可作副指标（角标/悬浮），不做主值

四、落地方案对比

方案做法工作量优点风险 / 代价
A. 前端直连（最小） CenterPanel 内加一段 15s 轮询 /api/sikong/devices + state 0.3d 改动面最小，可当天上线 与 MapView 重复轮询同一接口（两套请求、两套降级逻辑）
B. 提升到全局 Context
推荐		 把司空设备轮询提到 DashboardContext 单例（15s），MapView 与 CenterPanel 共用；KPI 取 droneCount 0.5d 一处轮询全局共享；降级/兜底统一；符合"长期彻底、不做临时 hack"；顺带消除重复请求 需回归地图标注（改数据来源），MapView 依赖项要核对
C. 后端聚合字段 /api/sikong/devices 响应补 dockCount/droneCount +0.2d 口径在后端唯一出处，前端零计算 单独做不解决重复轮询；建议与 B 合并执行

推荐组合：B + C（后端给口径、前端全局共享），方案 A 作为回滚路径

B 解决"取对源、不重复轮询"，C 解决"口径只在一处定义（后端）"，两者合计仅比 A 多 0.2d。

五、落地步骤

  1. 后端（口径唯一出处）：server/sikong.js 的 fetchMergedDevices() 返回体补 dockCount / droneCount / droneUnpaired（未配对无人机，正常为 0，异常可告警）
  2. 前端全局单例：DashboardContext 新增司空设备轮询（15s，与 MapView 现有节奏一致），暴露 sikongDevices / dockCount / droneCount / sikongAvailable
  3. 取数替换 + 语义拆分：CenterPanel 统计条 uavCount → droneCount（单位「架」）；气环境覆盖卡「无人机机场 N 座」改用 dockCount
  4. 降级策略：司空链路不可达（502/超时）时 KPI 显示 —（不显示 0）+ 离线角标；5 分钟内沿用上次成功值，避免闪变
  5. 类型契约：src/app/lib/api-types.ts 同步新增字段（纯新增，不破坏既有形状）
  6. 发布门禁：npm run verify（tsc + vite build）通过后再 scp 部署

六、冲突排查（改动影响面）

七、验收标准

  • 统计条「无人机」显示 4 架，且与 /api/sikong/devices 的 droneSn 计数一致（改动后复测）
  • 气环境覆盖卡显示「无人机机场 4 座」，文案与数值语义一致
  • 断开 dji-openapi 验证：KPI 显示「—」而非「0」（关键回归点）
  • 司空恢复后 15s 内自动回到 4 架，无需刷新页面
  • 地图司空机场标注、飞行中绿标、轨迹线不回归
  • npm run verify 通过 + 页面实测截图留档
