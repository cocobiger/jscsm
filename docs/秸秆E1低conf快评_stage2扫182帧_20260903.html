  • 背景：v5 stage2 灰度 24h 对 DJI 域 0 告警，前序离线抽测 182 帧全 0、max conf 0.122，疑似「模型无响应」或「0.15 阈值把微弱响应整体压掉」二选一。
  • 目的：用现网生产实载的 stage2 best.onnx，以低 conf（0.05/0.10/0.15）重扫 182 帧 DJI live_review，判定到底是 工作点锁死（调阈值可救） 还是 域缺口（必须重训） —— 这是段2 是否开训、往哪个方向训的决策 gate。
  • 约束：只读不改生产；与生产 worker 完全一致的推理口径（Detector / format=yolo / input_size=1280 / 与 config.json confSmoke=0.15 对齐）。

5结论与局限

判定维度结论
工作点锁死？排除 —— 若仅是阈值问题，降到 0.05 后应出现对真值框的命中；实际 IoU≥0.3 命中恒 0（三档一致）。
域缺口？实锤 —— 182 帧 DJI 真烟帧对 stage2 无可定位响应；弱响应为固定位置背景误检，非烟。
降阈值可救？不可救 —— 0.05 档 8 帧响应无一命中真值，救回的是误报不是召回。
段2 决策开训方向明确：DJI 真烟标签治理（v54 全量 984 帧人工治理，用户已拍板）→ stage2 epoch20.pt 续训（lr0=0.002）→ 双组 val 验收。

局限与风险（诚实标注）

  1. GT 标签质量：live_review 182 帧标签含 AI 预标成分（epoch20 预标 #53 时代产物），未经逐帧人工复核 —— 但即使标签有 ±10% 偏移，8 个检出框与其 GT 的质心距离都在数百像素量级，不影响「无命中」结论。
  2. 域内覆盖面：182 帧来自 2026-08-31 单日 3 机直播抽帧，时段/场景/距离分布有限；「远烟小目标」（30-130px）与「近烟大目标」均有覆盖但非均衡 —— 段1 DJI 标签审计（100 张 + v54 984 治理）会补全。
  3. 推理后端：E1 在 shell 环境无 CUDA lib 自动回退 CPU（onnxruntime 特性），权重与生产一致不影响结论；生产服务内确认 CUDAExecutionProvider。
