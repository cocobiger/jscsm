**这是"尺度缺口"，不是阈值/结构问题。** 现网模型从未见过 `<40px` 的烟，

## 三、训练参数与已验证的陷阱
`imgsz` 1920(day)/1280(night)｜`scale=0.5`｜**`mosaic=0.0`**｜`epochs=30`｜`batch` 3/6｜`nbs=64`｜`degrees=0`｜`rect=false`

- **`close_mosaic` 逻辑（`ultralytics/engine/trainer.py:459`）**：`if epoch == (epochs - close_mosaic)`。
  当前 `epochs=30, close_mosaic=50` → `30-50 = -20`，epoch 只到 29 ⇒ **永不触发关闭**。
  ⇒ **"开了 mosaic 会被 close_mosaic 立刻关掉"这个陷阱不存在**（先前怀疑有误，已实测纠正）。
- ⚠️ **真陷阱在 resume**：`trainer.py:1085` `if start_epoch > (epochs - close_mosaic)` → `> -20` **恒真**
  ⇒ **一旦以 `resume=` 续训，mosaic 会被立刻关掉**。（本项目是 `model=` 迁移学习，未受影响。）
- **开 mosaic 的建议**：`mosaic=1.0`（固定机位域建议 0.5 起做 A/B）+ 把 `close_mosaic` 改成合理值（如 5，让最后几轮用真实几何收敛）。
  但 mosaic **只解决"尺度不变性"**，不复制"远方"的另一半物理特征——**大气衰减**（对比度↓、偏蓝灰、细节丢失）
  ⇒ 必须**离线对正样本做退化仿真**（降对比度+蓝灰偏移+降饱和+轻模糊）配套。
  且**同尺度的真实难负（小块云）仍需真实采集/裁切**——mosaic 造不出真实的小云。

## 四、算力实测（`tmp/bench_smoke.py`，RTX 3090 24GB / torch 2.4.1+cu121 / ultralytics 8.4.125）
| 路径 | 耗时 |
|---|---|
| 生产路径 ONNX+ORT(CUDA) @1920×1920 | 白天 **50.5ms** ｜ 夜间 **49.9ms** |
| torch 端到端 predict（输入 1080p）imgsz=1920 | **32.0 ms** |
| 同上 imgsz=2560 | **60.8 ms** |
| 2×2 切片 ×4（每片 imgsz=1920） | **134 ms 合计**（单片 33ms） |
| 引擎自报 `last_ms` | **340 ms** |

- `last_ms` 定义（`app/main.py:400`）：`t_detect=time.time()` → `_use.predict(...)` → `last_ms`，
  即 **`predict()` 墙钟**（含 letterbox 预处理 + NMS）。**比纯推理高 6.8×** ⇒ 那约 290ms 的开销
  **本身就是一个比"改模型"更大的优化空间**（值得先查 letterbox/NMS/ORT 配置）。
- **⚠️ 用户反馈纠正**：每天飞行 ≤5 次、**大部分时间单机场起飞 = 单路视频分析**。
  ⇒ 我先前"6 路 × 2s = 3 帧/s ≈ 单卡满载、无余量"的约束**不成立**（那是 6 路同时在飞的最坏情形）。
  ⇒ 单路 interval=2s 预算 2000ms：**余量约 39×（按纯推理）/ 约 5.9×（按引擎端到端）**。
  ⇒ **解锁**：ROI 放大、2×2 切片、更高 imgsz 都能吃得下；更关键的是**可把 interval 2s→1s**，
    让**时序判别（长时中值背景 + 帧差）**真正可行——这才是分开"轻烟 vs 碎云"的正解。
- ⚠️ 仍需处理**多机重叠**（记忆里有"多机先后起飞后者中断前者"的现象）：
  **重活只在活跃流 ≤2 路时开启，超出则降级到廉价路径**。
- 服务器 RAM 充足（`mem_pct 24.7 / mem_gb 54.5`），显存 24GB（当前占用 ~12.5GB）。

### 结论与实现建议
- **屏蔽上方 10% 代价 ≈ 漏 1~2%**（可接受）；**20% 及以上会掉 8~15%（风险显著）**，别超过 10%。
- ⚠️ **固定百分比的 3 个隐患**：
  1. **相机角度/分辨率不恒定**：证据帧有 **8 种分辨率**（1440×1080 : 282、1280×720 : 233、960×720 : 128、
     2968×1732 : 56、2560×1329 : 49、1920×1080 : 10、2942×1732 : 8、1698×1278 : 1）。
     alert 组 **22% 的框在 y 0.8~1.0（贴底）** = 舱内/俯视帧，其"上方 10%"根本不是天空 ⇒ 规则失效。
  2. **更本质的先验是"接地"而非"高度"**：秸秆焚烧的烟**必然源于地面** ⇒ 判据应为"候选是否与地表连通/近接地"。
     这能同时解掉"云（悬空、四周被天空包围）vs 烟（自地表升起）"，且**不受相机角度影响**。
  3. **动态天际线可低成本实现（已查证）**：`gimbalPitch`/`gimbalYaw` 在
     **`/opt/jsc/dji-openapi/lib/telemetry.js:57-58` 已可取**（`payloadObj.gimbalPitch` 或 `data.gimbal.gimbal_pitch`）；
     `target-locator.js` 已记录约定（pitch：水平 0°、**向下为正**）。
     ⇒ 用 **云台 pitch + 相机垂直 FOV** 算天际线 y；俯视时 `y_horizon < 0` ⇒ **画面无天空 ⇒ 自动禁用屏蔽**。
     ⚠️ **straw-engine 目前完全没消费 pitch**（引擎只用 `droneInDock`）→ 需在"遥测 → 引擎"之间加一条字段。
- **落地形态（分级，禁止一刀切）**：
  - **L0（立即可做，零训练、可回滚）**：屏蔽区内的框**不推送、不计告警**，但**落库为 `source='low'`**
    ← 把屏蔽区变成**自动难负矿**，一举两得。门禁：离线回放历史 evidence，确认真实告警少了几条（已有数据 ≈1%）。
  - **L1**：固定 10% → **动态天际线**（OSD pitch 优先）；对**舱内/俯视帧自动禁用屏蔽**（可用现有 `osd_skip` 字段识别）。
  - **L2**：把"**接地先验 + 天际线距离**"作为**二级复核特征**（与时序判别一起）。
