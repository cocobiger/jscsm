## 三、后端 / 数据库 / 时区
- **🔴 时区坑家族（服务器 TZ=UTC）**：
  - 市局 API `monitortime` 是 CST，`new Date()` 在 UTC 机被当 UTC ⇒ 最新 8h 数据被判「未来」拒入库；修 `TZ=Asia/Shanghai` + SQLite `datetime('now','localtime')`。`[来源 2026-06-17]`
  - `warnings.created_at` 存的是**上海时间字符串（无时区）** ⇒ `Date.parse` 当 UTC、偏移 8h、聚合窗口/趋势**永不命中**；修：该格式追加 `+08:00`，趋势用 `date(created_at,'+8 hours')`（此处**不要**用 localtime）。`[来源 2026-07-08][来源 2026-07-10]`
- **`coll_streams` 表结构**：`id TEXT PRIMARY KEY, data_json TEXT`；流所有字段(name/url/protocol/lat/lon/category/thumbnail…)塞 `data_json`。**`PATCH /api/streams/:id` 强制覆盖 id，改 id 只能直接 `UPDATE`**。`[来源 2026-06-16]`
- **🔴 `apiFetch`（返回已解析 JSON）≠ `authFetch`（返回原生 Response）** ⇒ 写 `.then(r=>r.ok?r.json():fallback)` 会因 `r.ok===undefined` **恒走 fallback**（列表/下拉全空且不报错）。`[来源 2026-07-10]`
- `insertWarning` 写**列**用 camelCase `warningType`、写 `data_json` 用 `warning_type` ⇒ **两处都要设**，否则按列过滤查不到。`[来源 2026-07-08]`
- **校验/测试脚本勿直连生产 DB 写入**（曾把 `example.com` 测试告警、`V2_%` 测试规则写进生产库 → 前端裂图/403）；在 **DB 副本**上跑（顺带避 WAL 锁竞争）。`[来源 2026-07-10][来源 2026-07-12][来源 2026-07-28]`
- `window.open(需鉴权 URL)` 裸导航不带 token ⇒ 401；用 `authFetch` 取 blob + `createObjectURL`。`[来源 2026-07-13]`
